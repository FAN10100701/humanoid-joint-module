1 这是什么：把串口助手搬进浏览器

调电机、看编码器、抓 IMU 数据，几乎每个做机器人的人都会长期挂着一个串口调试助手。传统工具是桌面软件：装一次、换台电脑重装一次，画的曲线只能截图，解析规则只能靠记事本抄。这个工具换了个思路——用 Web Serial API 把串口助手做成一个网页，打开即用，解析规则、通道配色、图表布局全部记在配置里，可以导出一份 JSON 带走。

它对齐 Vofa+ 与市面上常见串口助手的基础能力：设备连接与参数配置、手动信号线控制、文本与 HEX 双模式收发、实时数据监视、波形的时域与频域展示、定时轮询与触发应答、预设快捷发送。在此之上补了三件更贴近「做实验」的事：一是时间线录制——把流过的帧录下来，事后回放、导出、复盘；二是面向 AI 的调试回路——一键导出一份自包含的调试包（配置 + 帧结构说明 + 通道统计 + 原始样本 + 失败样本），AI 读完就能给判断，而改完规则的验证靠「用缓存字节重放」完成，不必重烧固件；三是声明式显示——图表的种类、绑定哪几路数据、用什么公式换算、颜色与量程，都由一份 JSON 描述符决定，想加一个新视图不需要改代码。而界面布局本身也是围绕「调试时眼睛在看什么」设计的：串口监视器是绝对主视觉（占主区约 62% 的上半部分），波形带在下方的独立滚动区，中间一条分割线调比例——见下一节的界面分区说明。

整个应用是纯静态文件：没有后端、没有第三方运行时依赖、没有构建步骤，与本站其他页面共用一套离线缓存。它的解析内核、绘图内核、插件系统都是本站自研，源码可读、可改，也自带一份给 AI 读的开发说明（见第 7 节）。

它在站点里的位置
本站的工具页分两类：一类是纯浏览器内的计算与排版工具（如笔记排版器），一类是需要与硬件打交道的工具。串口调试助手属于后者，它是本站第一个与真实硬件通信的应用页，也是第一次把「设备连接」这件事带进学习流程——从这一页开始，你写的固件和数据可以在同一个浏览器里被观察、记录与回放。

2 能力清单

🔗 设备连接管理
端口选择授权、波特率/数据位/停止位/校验/硬流控配置、自动重连、失焦自动断连、DTR/RTS/BREAK 手动信号、CTS/DSR/DCD/RI 调制解调器信号实时读取。
👁 实时监视（主视觉）
串口监视器占主区约 62% 的上半部分，是默认面板与视觉重点；收发双向列表、时间戳、HEX 与文本双视图、收发光字节计数、解析成功/失败与校验和结果就地标注。时间戳有绝对时刻（23:06:40.125）与相对秒（1.235s／1m02.346s）两种口径，且与正文用不同颜色区分；字号可调，数字可标红，解析失败的行整行标红并写出原因。
🧭 文本解析
同时识别 key=value 与 key:value，整数小数统一处理；temp1/temp2 这类后缀数字保留为独立通道；一行里多个数值对全部提取。
🔢 HEX 结构表解析
按帧头/帧尾或长度字段定界收帧；字段表声明类型（int8~uint32、float32）、偏移、字节序与缩放系数；校验支持累加和、异或、累加和(16) 与 CRC16-Modbus。
📈 七种内置渲染器 + 可调节布局
时域折线、频域谱（FFT）、柱状图、仪表盘、数据表格、文本监视器、二维轨迹（李萨如/相图）。主区上下分割，中间一条分割线可拖拽调比例；每个面板固定高度、独立滚动（右下角可拖拽调高），互不拉伸；标题栏可全屏、收起、移到主位、加宽、移除。八色调色板自动分配并在通道表里显示色块。
📡 频域分析
零依赖手写 radix-2 FFT，加汉宁窗、单边幅值谱归一，峰值频率自动标注；采样率可取配置值，也可按相邻采样点的时间间隔反推。
⏱ 四种发送方式
手动发送（回车即发）、定时轮询、触发应答（收到含「匹配」内容自动回「应答」，带冷却与限流护栏）、预设发送（可绑单字符快捷键 + 期望回包 + 超时提示）。
🎞 录制 · 回放 · 导出
把流过的帧录成可回放的事故档案；连上设备或进演示后自动存档（滚动保留最近数据，上限可调），「暂停刷新」只停画面、不断开数据。导出解析结果 CSV（带 BOM，Excel 中文不乱码）、原始记录 CSV、JSON、BIN、TXT。
🧩 开源协议预设（一键套用）
内置 FireWater（Vofa+ 文本 name:value）、Teleplot（>name:value）、JustFloat（Vofa+ 二进制 float32 小端 + 帧尾 00 00 80 7F 定界）、匿名 V1.0（帧头 AA AA + 功能字 + 长度 + int16 大端数据 + SUM8）四套社区事实标准。点一下即套用，并立刻用缓存里的原始字节重放一遍，当场看效果。
🤖 面向 AI 的调试包
一键导出自包含 JSON：生效配置、帧结构人话说明、各通道统计（含颜色与量程）、最近 N 条原始 HEX 与解出值、全部失败样本与原因分布，并附一段可粘贴的纯文本摘要。配合「按当前规则重放缓存」，改完规则用缓存字节重解一遍，不必让硬件重跑。
🧩 声明式 DIY 显示
选渲染器 → 绑通道 → 写映射公式（如 (cur*24) 换算功率）→ 调量程与配色，全程是 JSON 配置，零代码执行；整套面板可导出为「面板包」分享。

界面怎么分区的：为什么监视器占主位、波形在下面

打开应用会看到四块区域，划分依据是「调试时眼睛真正盯着什么」——

区域位置与占比为什么这么分
A 顶栏顶部一行，固定只放「一眼要看到的状态」与「必须随手能点到的开关」：运行绿圆标（运行中/已暂停/未连接三态，一键暂停继续）、连接状态与设备 VID/PID、连接/演示/断开、收发光字节计数，右侧是帮助、AI、主题、恢复默认、收起左栏。
B 左栏左侧固定宽，可整栏收起「设置」性质的页签：设备 / 解析 / 显示 / 通道 / 发送 / 图表 / 录制 / 数据。调参是低频动作，不该占据主视觉；需要时展开，调完收起把宽度让给主区。
C 主区（上下分割）占屏最大，约 62% 给监视器串口监视器是绝对主导区域——调试时 90% 的时间在看打印。它占上方约 62%，波形带在下方的独立滚动区；中间一条分割线可拖拽调比例（双击复位、↑↓ 微调、Home 复位，比例会记住）。日志与波形各自独立滚动、互不拉伸：波形面板是固定高度的，监视器再高也不会把它压成一条竖线。主区还能全屏（波形区与分割线一起让位）或收起（只留标题条）。
D 发送条底部单行发送是高频动作，压缩成一行贴在底部，光标就近、不打断视线。

「主区工具条」上另外放了六个全局动作：全屏主区 / 收起主区 / 重置分割，以及「新图表」下拉 + 添加 / 清空面板 / 清空缓存。每个面板标题栏的六枚小按钮各司其职：主位上是 ⛶ 全屏与 ▭ 收起，工作区里是 ⇱ 移到主位、⇔ 加宽、▾ 收起、✕ 移除。

3 三步上手

第一步，把设备接上。点「连接设备」，浏览器会弹出一个端口列表（这一步必须由你亲手点，浏览器不允许网页自动打开串口）。选好设备后按你固件的设置调整波特率——默认 115200。如果你用的是 Arduino 或 ESP 系列，打开串口的瞬间 DTR 拉低会让板子复位，工具会显示「复位等待」，等它结束再发指令。手边没有硬件也不要紧：点「进入演示模式」，工具会用合成数据（位置/速度/电流/温度/母线电压五路正弦与噪声信号）走完全部流程，包括发送后的回显，用来验证解析规则刚刚好。

第二步，告诉它数据长什么样。串口来的数据无非两种形态。文本形态最常见，一行里写着键值对，比如 temp=25.3, cur:1.02——这种情况下什么都不用配，工具会自动把出现过的键建成通道，等宽曲线立刻就有。如果是 二进制帧，切到「十六进制」模式：先定义帧结构（帧头 AA55？有没有长度字段？帧尾是什么？有没有校验和？），再逐个字段声明它从第几个字节开始、是什么类型、要不要乘缩放系数。逗号分隔的演示帧结构可以点「套用示例」一键填入，对着改最快；如果你的设备已经在用开源生态的协议，直接点「解析」页签顶上的预设按钮（FireWater / Teleplot / JustFloat / 匿名 V1.0），工具会套好后立刻拿缓存数据重放一遍给你看效果。

第三步，挑一个顺眼的视图。切到「图表」页签（或直接用主区工具条上的「新图表」下拉），从七种渲染器里选一个加到工作区：看趋势用时域折线，查振荡找频域谱，盯一路即时值用仪表盘，看电机电流与位置的相位关系用二维轨迹。加进来的面板是固定高度的，右下角拖一下就能调高；点标题栏的「编辑」绑定它要显示哪几路通道、窗口显示最近多少点、纵轴要不要固定量程、每一路用什么颜色。想换算成更直观的量，就在「映射公式」里写一行算式：(cur*24) 把电流换算成功率，sqrt(ix*ix+iy*iy) 求合成矢量幅值。公式只支持四则运算与白名单数学函数，用通道名当变量，不支持任何脚本执行。

这套配置会自动存在本机浏览器里，下次打开还在原地。要换台电脑、或者分享给同学，去「数据」标签页复制配置，或者干脆导出「面板包」——里面装着图表框布局与通道配色。

4 数据格式说明：把「数据长什么样」一次配对

这一节回答两个最常被问到的问题：默认格式到底是什么？我自己的协议怎么配上去？先说结论——文本数据几乎不用配，二进制帧需要你把帧结构告诉它。配好之后，任何被解析出来的数值字段都会自动成为一路通道，可以直接进时域折线、频域谱、柱状图、仪表盘或表格。

文本格式：键值对，等号冒号都认

每行写一个或多个键值对，分隔符 = 与 : 都识别，数值对之间用逗号或空格分开，后缀数字（temp1 / temp2）会各自成为独立通道，数值支持整数、小数与科学计数法。若设备发的是没有换行的裸流，工具会在 60ms 静默后按一帧处理，不会一直卡着不动。

temp=25.3, cur:1.02
pos:90 vel=12.5
acc1=0.2, acc2=0.3

默认（演示）HEX 帧：共 11 字节

点「套用示例」或进入演示模式时用的就是这一帧。它不是任何标准协议，只是一个「结构完整、便于对照」的示例，你可以照它的形状改成自己的协议：

0-1AA 55帧头帧头 = AA55
2seq序号，0~255 循环，用来观察丢帧无需配置（演示帧自动填）

演示波形由三条互不相同的信号合成：pos = 90·sin(2π·0.5t)、cur = 3.2·sin(2π·0.5t+0.6)、temp = 42 + 3·sin(2π·0.02t)。所以时域上能看到慢变与快变叠加，频域谱上在 0.5Hz 附近有明确峰值——这也正好用来验证频域面板工作是否正常。

自定义 HEX 格式：在「解析」页签逐项配置

  1. 打开「解析」页签，模式选「十六进制」。
  2. 帧结构：填帧头（如 AA55）、帧尾（如 0D0A）；留空表示不按该方式定界。
  3. 长度字段：偏移（相对整帧起始，含帧头）、字节数（0 = 不用，1~4）、含义（载荷长度 / 整帧长度）。
  4. 校验：选类型（无 / 累加和8 / 异或8 / 累加和16 / CRC16-Modbus），再填校验起始与结束字节（-1 表示到载荷末尾）。
  5. 字段表：点「＋新增字段」，逐个填键名、类型（int8~uint32、float32）、偏移、长度、缩放系数、是否大端。
  6. 回「设备」页签点「进入演示模式」——演示数据会按你刚配好的帧结构合成，手边没有硬件也能确认「帧收得齐、字段解得对、通道画得出」。
六个最容易踩的坑
  • 长度字段的偏移是相对整帧起始（含帧头），不是相对载荷，也不是相对帧头之后。
  • 长度字段只按小端解析（当前不支持大端长度字段）。
  • 校验和固定在帧尾，按类型占 1 或 2 字节。
  • 长度字段与帧尾同时填时以长度字段为准，帧尾只参与帧长计算。
  • 未知字段类型会被当作无符号整数处理，不会让整帧作废——但也容易掩盖配错，建议按实际类型选。
  • 不支持位域与变长字段；字段的偏移与长度必须落在帧内，否则整帧判为越界。
解析出来之后怎么画？ 数值字段会自动建通道，去「图表」页签加一个时域折线（看趋势）或频域谱（找振荡）即可；要显示非数值内容（比如原始行、原始 HEX 字节）用文本监视器。想让某个字段按公式换算（例：(cur*24) 求功率），在面板「编辑」里写映射公式，用通道名当变量。

开源协议预设：四套社区事实标准，一键套用

如果你的设备已经在用某个开源生态的协议，不必从零拼帧结构——「解析」页签顶上有四枚预设按钮，点一下即套用，并且会立刻用缓存里的原始字节按新规则重放一遍，当场看效果（不必让硬件重跑）。套用后仍可手动微调任何一项。

关于匿名 V1.0 的口径分歧：不同来源对「长度字段到底表示数据段字节数还是整帧字节数」「校验和从帧头还是从长度字节开始累加」说法不一。这里采用野火官方教材与高校论文一致的口径：长度 = 数据段字节数，校验 = 从帧头累加到校验和之前。如果你手上的固件用的是另一种口径，套用预设后在「长度字段 → 含义」与「校验 → 起始」两处改一下即可，再用「按当前规则重放缓存」当场验证，不必重烧固件。

5 发送与录制：把调试过程变成可复盘的材料

定时轮询适合周期性问一个寄存器：填好内容和间隔（最小 20ms），勾上启用即可，工具会用与配置对账的方式管理计时器，改内容或改间隔下一次发送就生效，不用重启。触发应答适合「设备上报某状态，我立刻回一条控制字」的闭环：接收内容里出现你写的匹配词就自动发送应答。这里有一层保护——单条规则 250ms 冷却，自动发送每秒最多 30 次；如果匹配词与应答内容互相包含，工具会限流并提示，避免把串口打满。预设发送是给常用指令准备的：绑一个单字符快捷键（焦点不在输入框时生效），顺手敲一下就把指令发出去；还能填「期望回包」与超时时间，收到就提示往返耗时，超时也会明确告诉你——这比盯着屏幕数秒数靠谱。

调完一轮，最珍贵的往往是中间那段异常数据。录制标签页点「开始录制」，工具会把这期间流过的每一帧（含时间戳、方向、原始 HEX、文本与解析值）存进内存；停止后可以回放——按原始时间关系重新喂给图表，让当时的抖动重演一遍——也可以导出成 JSON 存档、或者粘回另一台机器继续分析。需要长时间留档时，用「数据」标签页导出解析结果 CSV 或原始记录 CSV：CSV 带 UTF-8 BOM，Excel 双击打开中文不乱码。

为什么录制数据只放内存？ 一次几分钟的 50Hz 录制就有上万帧，写进浏览器的 5MB 本地存储只会把配额打爆，连你的配置一起写坏。所以录制是「用完即导」的定位：想看就回放，想留存就导出 JSON 文件，配置则始终独立保存。

这个应用不是一次性页面，而是按「可被复用的基座」写的。它把串口调试这类应用拆成了十四个职责单一的模块，全部挂在同一个命名空间 window.SerialLab 下，模块之间不互相持有引用、只通过事件总线通信：

同时，应用目录里自带三份给 AI 直接读取的文档：llms.txt（速览与关键约定）、AGENTS.md（工程硬约束与协作规则）、skills/html-webserial-app/SKILL.md（从零开发同类应用的完整流程与踩坑清单）。如果你想让 AI 帮你做一件类似的事——做一个网页端 CAN 调试器、一个串口协议分析器，或者在这个应用上加新图表、新发送方式——把这三份文档连同对应模块贴给它，比口头描述快得多。应用内「AI 开发提示词」按钮还提供了一份浓缩版，可一键复制或下载为 txt。

更直接的一条路：让 AI 来读你的现场数据。调试硬件时最费时间的往往不是点按钮，而是「把现在的现象讲清楚」——截图讲不全，复制日志又丢掉了解析上下文。所以这个应用把「给 AI 的输入」做成了一个按钮：「显示」页签里的 「导出 AI 调试包」会生成一份自包含 JSON，里面装着

  • 当前配置：串口参数、时间戳口径与全部显示设置、图表框清单——AI 据此知道你是怎么配的，给出的建议不会答非所问；
  • 帧结构人话说明：文本模式说明分隔符与数值正则；二进制模式逐项列出帧头、长度字段的位置与含义、每个数据字段的偏移/类型/端序/缩放、校验类型与区间、帧尾；
  • 可用预设清单：四套开源协议的名字与结构摘要，让 AI 知道还能换成什么；
  • 各通道统计：键名、标签、单位、颜色、精度、计数、末值、极值、均值、极差，以及是否数值恒定（恒定通道常常意味着占位字段或偏移错位）；
  • 最近 N 条原始记录：每条都带原始 HEX 与解出的数值，AI 可以据此离线复算；
  • 全部失败样本与原因分布：校验和不符、长度越界、未识别出键值对各占多少，附具体帧；
  • 一段给 AI 的排查提示：例如「当前未设帧头，长噪声下容易串帧」「文本模式下大量未识别，多半是分隔符或数值正则不符」。

同时会产出一段纯文本摘要并自动复制到剪贴板——不想传文件时直接粘进对话框即可。拿到 AI 给出的规则修改后，回到应用「按当前规则重放缓存」，用缓存里的原始字节重新解一遍就能验证，形成「AI 读数据 → 发现规律 → 改规则 → 当场重放验证」的闭环，不必让硬件重跑。这也是「实时暂停继续」在架构上要配合的一环：运行绿圆标暂停的只是屏幕刷新，数据仍在后台缓冲，所以暂停期间的数据同样能进调试包、同样能被重放。

拿它当基座可以做什么：把 transport 换成 WebSocket 或 Web Bluetooth 传输层，整套解析、绘图、录制与导出链路可以原样复用；把 plugins 的渲染器注册表加一项，就有了新图表类型；把 parser 的字段表扩成完整的 CAN 报文定义，就有了一个浏览器内的总线调试器。三条路都不需要改动数据管线的其他部分。

AI 自动化调试接入：让 AI 直接读串口、跑判据（MCP）

上面两条路（调试包 / 复制提示词）仍需要人做一次「搬运」。V2.2.2 起补上了完全自动的一条：仓库里的 _本地工具/serial-bridge 是一个本地串口桥（Node.js + serialport），它直接 require 本应用的 9 个真源模块复用同一份解析内核——桥解析出的通道值与网页端逐字节一致，不存在两套实现各算各的。桥已封装为 MCP server（Model Context Protocol），接入后任何支持 MCP 的 AI 会话都能直接调用五个工具：

MCP 工具作用
serial_list枚举本机可用串口
serial_read按当前规则采一段数据（可指定时长/波特率/协议预设，产出通道值 + 完整调试包）
serial_write向串口发送指令（HEX 或文本）——危险动作，AI 会先征求你确认
serial_parse离线解析一段 HEX（不碰硬件）：改规则试错、离线重放的主力工具
serial_assert判据断言：--expect "x>0.5; y.max<=1"，退出码 0=通过 / 2=不通过——AI 自动判定「这轮改得对不对」的机器可读出口

三步接入（详细命令与参数见 _本地工具/serial-bridge/README.md）：

  • ① 安装：进 _本地工具/serial-bridge 执行 npm install（Node 18+，仅本地工具目录有依赖，站点本体仍是零依赖）；
  • ② 在 AI 工具的 MCP 配置里加一个 server：{"command": "node", "args": ["<仓库根>/_本地工具/serial-bridge/bridge.mjs", "mcp"]}，路径换成你自己的仓库位置；
  • ③ 在对话里直接说「读一下串口」「用 FireWater 预设采 3 秒」「断言 x>0.5」即可。

除了 MCP，还有两条不依赖任何协议的通路：浏览器持续落盘（应用内勾选「持续写入本地文件」，NDJSON 逐行追加，AI 拿文件路径就能读）与 HTTP 收件箱（勾选「HTTP 上报」+ 运行 python _本地工具/serial-inbox.py，数据实时落到 latest.brief.txt 等文件）。AI 拿到导出的数据文件后，可以像操作普通文件一样下载、diff 两轮数据、甚至帮你 git 提交上传 GitHub——这些都不需要额外权限，走的就是普通文件系统。隐私边界：串口数据只在你的本机流转，桥与收件箱没有任何上传代码；AI 能读到什么，取决于你让它读哪个文件。

8 常见问题速查

现象先查这里
点「连接设备」没有任何反应或提示不支持看页面顶部横幅给的具体原因：多半是用了 file:// 或非 Chromium 浏览器
连上了但一条数据都没有波特率是否与固件一致；是否在「复位等待」窗口内；文本模式下设备是否发送了换行符（没有换行的裸流会等 60ms 静默后按一帧显示）
有数据但通道一直是空的数据形态与解析模式不匹配：文本模式只认 键=值／键:值；二进制帧要切到 HEX 模式并配置字段表
HEX 模式收到的是残帧、校验和一直不匹配逐项核对帧结构：帧头写对了吗？长度字段的偏移是相对「整帧起始（含帧头）」的吗？有校验和时有没有选对类型？长度字段的含义是「载荷长度」还是「整帧长度」？
曲线像一团噪声纵轴量程被固定住了；点图框「编辑」把纵轴上限/下限清空即回到自动量程
波形被监视器压成一条竖线 / 拉得看不出来V2.2.1 起波形面板是固定高度、独立滚动的，不会被监视器拉长。若仍觉得挤：双击中间的分割线复位到 62%，或拖分割线把主区比例调小、拖面板右下角把手把波形调高，也可以点「收起主区」把监视器压成标题条
时间戳显示的是「多少 s」，不是真实时刻那是「相对秒」口径。切到「显示 → 时间戳口径 → 绝对时刻」即可显示 23:06:40.125（V2.2.1 起默认就是绝对时刻）
点了「暂停刷新」，数据会不会丢不会。暂停只停屏幕重绘，传输、分帧、解析与缓冲照常进行；恢复后数据都在，暂停期间的数据同样能进 AI 调试包、也能被重放
换了协议、改完规则想验证，要重烧固件吗不用。点「显示 → 按当前规则重放缓存」，用缓存里的原始字节按新规则重新解一遍即可当场看结果
发送没反应先看底部提示条：未连接、复位等待中、或 HEX 内容不是偶数位十六进制，都会明确提示
配置丢了换浏览器、清缓存、隐私模式都会导致本地存储不可用；重要配置请用「导出文件」留一份
一句总结
串口调试助手的价值不在「多一个能画曲线的界面」，而在把调试过程变成可保存、可迁移、可复盘的材料：规则是 JSON、布局是 JSON、数据可录制可回放可导出，连图表的画法都能被描述成一份配置。做到这一步，它就不只是工具，而是一份可以继续长的基座。
