1 这是什么：把串口助手搬进浏览器

调电机、看编码器、抓 IMU 数据，几乎每个做机器人的人都会长期挂着一个串口调试助手。传统工具是桌面软件：装一次、换台电脑重装一次，画的曲线只能截图，解析规则只能靠记事本抄。这个工具换了个思路——用 Web Serial API 把串口助手做成一个网页，打开即用，解析规则、通道配色、图表布局全部记在配置里，可以导出一份 JSON 带走。

它对齐 Vofa+ 与市面上常见串口助手的基础能力：设备连接与参数配置、手动信号线控制、文本与 HEX 双模式收发、实时数据监视、波形的时域与频域展示、定时轮询与触发应答、预设快捷发送。在此之上补了两件更贴近「做实验」的事：一是时间线录制——把流过的帧录下来，事后回放、导出、复盘；二是声明式插件——图表的种类、绑定哪几路数据、用什么公式换算、颜色与量程，都由一份 JSON 描述符决定，想加一个新视图不需要改代码。

整个应用是纯静态文件：没有后端、没有第三方运行时依赖、没有构建步骤，与本站其他页面共用一套离线缓存。它的解析内核、绘图内核、插件系统都是本站自研，源码可读、可改，也自带一份给 AI 读的开发说明（见第 7 节）。

它在站点里的位置
本站的工具页分两类：一类是纯浏览器内的计算与排版工具（如笔记排版器），一类是需要与硬件打交道的工具。串口调试助手属于后者，它是本站第一个与真实硬件通信的应用页，也是第一次把「设备连接」这件事带进学习流程——从这一页开始，你写的固件和数据可以在同一个浏览器里被观察、记录与回放。

3 三步上手

第一步，把设备接上。点「连接设备」，浏览器会弹出一个端口列表（这一步必须由你亲手点，浏览器不允许网页自动打开串口）。选好设备后按你固件的设置调整波特率——默认 115200。如果你用的是 Arduino 或 ESP 系列，打开串口的瞬间 DTR 拉低会让板子复位，工具会显示「复位等待」，等它结束再发指令。手边没有硬件也不要紧：点「进入演示模式」，工具会用合成数据（位置/速度/电流/温度/母线电压五路正弦与噪声信号）走完全部流程，包括发送后的回显，用来验证解析规则刚刚好。

第二步，告诉它数据长什么样。串口来的数据无非两种形态。文本形态最常见，一行里写着键值对，比如 temp=25.3, cur:1.02——这种情况下什么都不用配，工具会自动把出现过的键建成通道，等宽曲线立刻就有。如果是 二进制帧，切到「十六进制」模式：先定义帧结构（帧头 AA55？有没有长度字段？帧尾是什么？有没有校验和？），再逐个字段声明它从第几个字节开始、是什么类型、要不要乘缩放系数。逗号分隔的演示帧结构可以点「套用示例」一键填入，对着改最快。

第三步，挑一个顺眼的视图。切到「插件」标签页，从七种渲染器里选一个加到工作区：看趋势用时域折线，查振荡找频域谱，盯一路即时值用仪表盘，看电机电流与位置的相位关系用二维轨迹。然后点这个图框上的「编辑」，绑定它要显示哪几路通道、窗口显示最近多少点、纵轴要不要固定量程、每一路用什么颜色。想换算成更直观的量，就在「映射公式」里写一行算式：(cur*24) 把电流换算成功率，sqrt(ix*ix+iy*iy) 求合成矢量幅值。公式只支持四则运算与白名单数学函数，用通道名当变量，不支持任何脚本执行。

这套配置会自动存在本机浏览器里，下次打开还在原地。要换台电脑、或者分享给同学，去「数据」标签页复制配置，或者干脆导出「面板包」——里面装着图表框布局与通道配色。

4 数据格式说明：把「数据长什么样」一次配对

这一节回答两个最常被问到的问题：默认格式到底是什么？我自己的协议怎么配上去？先说结论——文本数据几乎不用配，二进制帧需要你把帧结构告诉它。配好之后，任何被解析出来的数值字段都会自动成为一路通道，可以直接进时域折线、频域谱、柱状图、仪表盘或表格。

文本格式：键值对，等号冒号都认

每行写一个或多个键值对，分隔符 = 与 : 都识别，数值对之间用逗号或空格分开，后缀数字（temp1 / temp2）会各自成为独立通道，数值支持整数、小数与科学计数法。若设备发的是没有换行的裸流，工具会在 60ms 静默后按一帧处理，不会一直卡着不动。

temp=25.3, cur:1.02
pos:90 vel=12.5
acc1=0.2, acc2=0.3

默认（演示）HEX 帧：共 11 字节

点「套用示例」或进入演示模式时用的就是这一帧。它不是任何标准协议，只是一个「结构完整、便于对照」的示例，你可以照它的形状改成自己的协议：

偏移字节含义对应配置
0-1AA 55帧头帧头 = AA55
2seq序号，0~255 循环，用来观察丢帧无需配置（演示帧自动填）
306长度字段 = 载荷长度 6长度字段：偏移 3 / 1 字节 / 载荷长度
4-5posint16 小端，×0.01（度）字段 pos / int16 / 偏移 4 / 缩放 0.01
6-7curint16 小端，×0.001（安培）字段 cur / int16 / 偏移 6 / 缩放 0.001
8-9tempint16 小端，×0.01（摄氏度）字段 temp / int16 / 偏移 8 / 缩放 0.01

演示波形由三条互不相同的信号合成：pos = 90·sin(2π·0.5t)、cur = 3.2·sin(2π·0.5t+0.6)、temp = 42 + 3·sin(2π·0.02t)。所以时域上能看到慢变与快变叠加，频域谱上在 0.5Hz 附近有明确峰值——这也正好用来验证频域面板工作是否正常。

自定义 HEX 格式：在「解析」页签逐项配置

  1. 打开「解析」页签，模式选「十六进制」。
  2. 帧结构：填帧头（如 AA55）、帧尾（如 0D0A）；留空表示不按该方式定界。
  3. 长度字段：偏移（相对整帧起始，含帧头）、字节数（0 = 不用，1~4）、含义（载荷长度 / 整帧长度）。
  4. 校验：选类型（无 / 累加和8 / 异或8 / 累加和16 / CRC16-Modbus），再填校验起始与结束字节（-1 表示到载荷末尾）。
  5. 字段表：点「＋新增字段」，逐个填键名、类型（int8~uint32、float32）、偏移、长度、缩放系数、是否大端。
  6. 回「设备」页签点「进入演示模式」——演示数据会按你刚配好的帧结构合成，手边没有硬件也能确认「帧收得齐、字段解得对、通道画得出」。
六个最容易踩的坑
  • 长度字段的偏移是相对整帧起始（含帧头），不是相对载荷，也不是相对帧头之后。
  • 长度字段只按小端解析（当前不支持大端长度字段）。
  • 校验和固定在帧尾，按类型占 1 或 2 字节。
  • 长度字段与帧尾同时填时以长度字段为准，帧尾只参与帧长计算。
  • 未知字段类型会被当作无符号整数处理，不会让整帧作废——但也容易掩盖配错，建议按实际类型选。
  • 不支持位域与变长字段；字段的偏移与长度必须落在帧内，否则整帧判为越界。
解析出来之后怎么画？ 数值字段会自动建通道，去「插件」页签加一个时域折线（看趋势）或频域谱（找振荡）即可；要显示非数值内容（比如原始行、原始 HEX 字节）用文本监视器。想让某个字段按公式换算（例：(cur*24) 求功率），在面板「编辑」里写映射公式，用通道名当变量。

5 发送与录制：把调试过程变成可复盘的材料

定时轮询适合周期性问一个寄存器：填好内容和间隔（最小 20ms），勾上启用即可，工具会用与配置对账的方式管理计时器，改内容或改间隔下一次发送就生效，不用重启。触发应答适合「设备上报某状态，我立刻回一条控制字」的闭环：接收内容里出现你写的匹配词就自动发送应答。这里有一层保护——单条规则 250ms 冷却，自动发送每秒最多 30 次；如果匹配词与应答内容互相包含，工具会限流并提示，避免把串口打满。预设发送是给常用指令准备的：绑一个单字符快捷键（焦点不在输入框时生效），顺手敲一下就把指令发出去；还能填「期望回包」与超时时间，收到就提示往返耗时，超时也会明确告诉你——这比盯着屏幕数秒数靠谱。

调完一轮，最珍贵的往往是中间那段异常数据。录制标签页点「开始录制」，工具会把这期间流过的每一帧（含时间戳、方向、原始 HEX、文本与解析值）存进内存；停止后可以回放——按原始时间关系重新喂给图表，让当时的抖动重演一遍——也可以导出成 JSON 存档、或者粘回另一台机器继续分析。需要长时间留档时，用「数据」标签页导出解析结果 CSV 或原始记录 CSV：CSV 带 UTF-8 BOM，Excel 双击打开中文不乱码。

为什么录制数据只放内存？ 一次几分钟的 50Hz 录制就有上万帧，写进浏览器的 5MB 本地存储只会把配额打爆，连你的配置一起写坏。所以录制是「用完即导」的定位：想看就回放，想留存就导出 JSON 文件，配置则始终独立保存。

同时，应用目录里自带三份给 AI 直接读取的文档：llms.txt（速览与关键约定）、AGENTS.md（工程硬约束与协作规则）、skills/html-webserial-app/SKILL.md（从零开发同类应用的完整流程与踩坑清单）。如果你想让 AI 帮你做一件类似的事——做一个网页端 CAN 调试器、一个串口协议分析器，或者在这个应用上加新图表、新发送方式——把这三份文档连同对应模块贴给它，比口头描述快得多。应用内「AI 开发提示词」按钮还提供了一份浓缩版，可一键复制或下载为 txt。

拿它当基座可以做什么：把 transport 换成 WebSocket 或 Web Bluetooth 传输层，整套解析、绘图、录制与导出链路可以原样复用；把 plugins 的渲染器注册表加一项，就有了新图表类型；把 parser 的字段表扩成完整的 CAN 报文定义，就有了一个浏览器内的总线调试器。三条路都不需要改动数据管线的其他部分。

8 常见问题速查

现象先查这里
点「连接设备」没有任何反应或提示不支持看页面顶部横幅给的具体原因：多半是用了 file:// 或非 Chromium 浏览器
连上了但一条数据都没有波特率是否与固件一致；是否在「复位等待」窗口内；文本模式下设备是否发送了换行符（没有换行的裸流会等 60ms 静默后按一帧显示）
有数据但通道一直是空的数据形态与解析模式不匹配：文本模式只认 键=值／键:值；二进制帧要切到 HEX 模式并配置字段表
HEX 模式收到的是残帧、校验和一直不匹配逐项核对帧结构：帧头写对了吗？长度字段的偏移是相对「整帧起始（含帧头）」的吗？有校验和时有没有选对类型？长度字段的含义是「载荷长度」还是「整帧长度」？
曲线像一团噪声纵轴量程被固定住了；点图框「编辑」把纵轴上限/下限清空即回到自动量程
发送没反应先看底部提示条：未连接、复位等待中、或 HEX 内容不是偶数位十六进制，都会明确提示
配置丢了换浏览器、清缓存、隐私模式都会导致本地存储不可用；重要配置请用「导出文件」留一份
一句总结
串口调试助手的价值不在「多一个能画曲线的界面」，而在把调试过程变成可保存、可迁移、可复盘的材料：规则是 JSON、布局是 JSON、数据可录制可回放可导出，连图表的画法都能被描述成一份配置。做到这一步，它就不只是工具，而是一份可以继续长的基座。
