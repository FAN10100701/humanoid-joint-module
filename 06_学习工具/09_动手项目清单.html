🎯 使用方法
1. 按顺序做:每个项目的前置 chip 链接指向本站对应页面,先读再做

🟢 L1 · 点亮与读取(半天~1天)

目标:让硬件"开口说话"。只需开发板 + 云台电机,预算 ¥100~200。
P1 · 开环旋转一台无刷电机
前置:01-02 原理动画硬件:Arduino/ESP32 + SimpleFOC mini 或 DRV8313 + 云台电机(2208)
内容:接线(三相+编码器先不接)→ 刷 SimpleFOC 开环示例 → 观察 U/V/VW 六步换相。
验收:电机匀速转动,调速旋钮顺滑,电机不发烫(开环发热是正常的,理解为什么——励磁没对准转子)。
P2 · 读编码器并画出角度曲线
前置:02-12 标定专题硬件:上项 + AS5600/MT6701 磁编码器
内容:I2C/SPI 读原始值 → 转机械角 → 串口上传 → 串口绘图仪显示;手转一圈检查单调性与圈数。
验收:角度 0~360° 单调无跳变;方向与定义一致;静止噪声 <0.1°。

🟢 L2 · 闭环控制入门(1~2周)

目标:第一次体验"电机变刚性"。仍是云台电机平台。
P3 · 电流环 + 速度环闭环
前置:02-08 调参手册硬件:同上(需电流采样版驱动器)
内容:零位标定 → 带宽法算电流环 PI → 速度环整定 → 记录阶跃曲线。
验收:速度阶跃超调 <15%;手拧电机能感到"弹簧般"回正;全程无疯转无炸管。
P4 · 位置控制 + 仿真的手感校准
前置:06-04 代码实验室(PID 实验)硬件:同上
内容:先在代码实验室把"超调 5%/收敛 2s"调出来,再把同结构参数搬到真机微调;对比仿真与实机的差异并记录原因(摩擦/齿槽/延迟)。
验收:真机位置阶跃稳态误差 <1°;写一段 200 字的"仿真vs实机差异清单"。

🟡 L3 · 关节模组级(2~4周)

目标:拥有一个真正的"关节"。预算 ¥800~2000(电机+减速器+驱动板)。
P5 · 组装一个关节模组并完成全套标定
前置:02-12 标定 · 02-07 传感器硬件:无框力矩电机/云台电机 + 谐波或行星减速器 + 输出端编码器
内容:机械装配 → 双编码器(电机端+输出端)联调 → 电角度零位/关节零位/限位 → 力矩砝码标定。
验收:零位重复标定偏差 <0.5° 电角度;力矩标定线性度 R²>0.99;软限位触发自动减速。
P6 · CAN 总线双节点通信
前置:04-23 通信升级路线硬件:两块驱动板(或板+USB-CAN)+ 120Ω 电阻×2
内容:ID/滤波器配置 → 位置/速度/电流指令帧 → 心跳与错误帧 → 总线负载测试(1Mbps 下 80% 负载)。注意电机干扰下的丢帧率。
验收:连续 1h 丢帧率 <0.01%;断节点后主机 100ms 内报错。
P7 · 浏览器复现倒立摆 + RL 训练(纯软件)
前置:04-15 RL实验室 · 06-04 代码实验室硬件:无(也可以用 Python 复刻)
内容:在 RL 实验室完成 1000 回合训练;再改奖励(失败罚金、力矩惩罚)观察策略变化,写对比笔记。
验收:平均奖励 >1000;能说出 3 个奖励改动各自导致的策略变化。

🟠 L4 · 系统集成(1~2月)

目标:从"一个关节"到"一套系统"。
P8 · 关节阻抗控制(力控入门)
前置:3D解剖(力控仿真) · 02-08 调参硬件:P5 的关节 + 刚性安装座
内容:实现 K-x + D-ẋ + x_ref 阻抗律;拖动示教(零力矩感);刚度/阻尼扫参画"手感地图"。
验收:拖动示教全程无抖动;外力冲击不飞车;同一位置指令下 K 换 10 倍,末端偏差变化符合 1/K 趋势。
P9 · ROS2 节点驱动仿真关节
前置:04-09 ROS2入门 · 04-14 ros2_control硬件:Ubuntu PC(或虚拟机)
内容:写 hardware_interface 把 P5/P8 的关节包进 ros2_control;RViz 里显示状态;rqt 发指令。
验收:`ros2 control` 列出关节;500Hz 控制循环 overrun <1%。
P10 · MuJoCo 单摆/双摆 RL 训练
前置:04-04 仿真与RL · 04-15 RL实验室硬件:PC + Python
内容:mujoco-py 建摆模型 → Stable-Baselines3 PPO 训 swing-up → 可视化策略。
验收:10 次评估全部 5s 内立起并保持;能解释 PPO 与 Q-Learning 的两个本质区别。

🔴 L5 · 整机级(季度级)

目标:腿组与整机——从这里走向真正的机器人工程师。
P11 · 双关节腿组摆动与跳跃
前置:P8 + 04-24 WBC/步态硬件:2×关节 + 铝型材腿组 + 电源吊挂架
内容:摆线轨迹跟踪(位置) → 竖直跳跃(SLIP 简化) → 落地缓冲(阻抗切换)。
验收:摆动轨迹跟踪误差 <3°;连续 10 次跳跃无失稳;落地冲击力矩不超过限幅。
P12 · URDF 建模 + MoveIt 轨迹规划上真机
前置:04-10 URDF/MoveIt · 04-13 进阶硬件:2~3 自由度臂/腿 + ROS2 主机
内容:为你的机构写 URDF(含限位/惯量)→ MoveIt2 规划 → 轨迹插值下发给关节 → 碰撞场景测试。
验收:避障路径成功率 >95%;规划-执行延迟 <100ms;急停后可安全复位。

2 从项目到简历:怎么写才有说服力

同样是做过 P3(电流环+速度环闭环),简历上写"熟悉 FOC 与电机控制"和写出量化结果,在面试官眼里是完全不同的两种人。写项目经历遵循一个固定句式:平台约束 + 你做了什么 + 量化验收 + 一句根因分析。对照:

反例:「熟悉 SimpleFOC,做过电机闭环控制。」
  ——没有平台、没有指标、没有思考,无法追问,也无法采信。

正例:「在 ESP32 + SimpleFOC mini + 2804 云台电机上完成电流/速度双环整定:
  用带宽法整定电流环 PI,速度阶跃超调从 38% 降到 12%(目标 <15%);
  定位到编码器线缆未屏蔽引入的噪声毛刺,改双绞+磁环后静止噪声 0.08°。
  遗留:低速爬行现象,怀疑摩擦补偿缺失(下一步对照 02-08 第 4 节)。」

正例的四个要素分别对应:平台(可复现)、方法(懂原理)、指标(会验收)、根因(有工程思维)。写完以后自查一遍:每个数字都能被追问两层吗(怎么测的?为什么是这个目标值?)——答不上来的数字删掉,那就是面试坑。更多写法与追问套路见 06-07 大厂面试专题 的 STAR 法则一节。

不必从 L1 做到 L5 全做完。先定目标,再按预算反选项目组合:

路线预算项目组合适合目标
软件仿真路线≈ ¥0(PC 即可)P7 → P10 → P12(建模部分)算法/RL 岗位;先验证兴趣再投入硬件

4 本节自测

1. 做 P3(电流环+速度环)之前必须先完成什么?为什么?
💡 解析:闭环的前提是反馈正确,标定(02-12)永远先于整定(02-08)。位置环是三环最外层,必须最后整定。
2. L4 的 P8(阻抗控制)与 L2 的 P4(位置控制)本质区别是?
💡 解析:阻抗控制把"硬度"本身变成可编程参数——同一位置指令下 K 小则软(安全、拖动示教),K 大则硬(精确定位)。这是人形机器人力控的入门钥匙。
3. 项目顺序为什么强调"P5 完成全套标定"后才进入 P8 力控?
💡 解析:阻抗律输出的是力矩参考,力矩刻度错 10%,所有 K/D 扫参结论都失真。工程项目的"依赖关系"正是本清单排序的逻辑。
4. P1 开环旋转时电机发烫,正确的理解是?
💡 解析:开环没有编码器反馈,六步换相无法知道转子真实位置,励磁方向与转子没对齐,电流白白变成热——页面 P1 明确写「开环发热是正常的,理解为什么——励磁没对准转子」。把正常发热当故障去换电机,是新手最常见的错误认知。
5. P6 CAN 双节点通信的验收标准要求,断掉一个节点后主机应多久内报错?
💡 解析:页面 P6 验收标准为「断节点后主机 100ms 内报错」,这考验的是心跳帧与错误帧的实时性;同一项目还要求连续 1h 丢帧率 <0.01%。验收标准里每个数字都是对系统可靠性的硬性要求。
6. 关于本页末尾的「三条军规」,下列说法正确的是?
💡 解析:三条军规是①预算按级升——L3 之前不要买贵的,L5 之前先吊挂;②每个项目都留档(参数、曲线、失败照片);③遇到故障先走决策树再换硬件。A、B、D 分别违反这三条,是「一步到位」「做完就删」「凭感觉动手」三类常见错误认知。
📌 本节要点速查:①12 个项目按 L1~L5 难度分级,从开环点亮(预算 ¥100~200)到整机级(季度级)循序渐进;②项目之间有依赖顺序——先标定(02-12)再整定(02-08),先完成 P5 全套标定再进 P8 力控;③每个项目都有硬性验收标准,达标才算完成(如 P2 静止噪声 <0.1°、P6 丢帧率 <0.01%、P11 摆动误差 <3°);④三条军规:预算按级升、每个项目留档、遇故障先走决策树。
