# 网页端串口调试助手 · 开发与二次开发

- 从零做一个浏览器里的串口 / 设备调试工具（实时监视 + 解析 + 绘图 + 发送 + 导出）。

## 一、先立三条底线，再谈功能

1. **安全上下文是硬门槛**。`navigator.serial` 只在 **HTTPS 或 http://localhost** 下存在；`file://` 下 `requestPort()` 会被直接拒绝。
   因此「导出单文件离线版双击打开」只能看界面与演示数据，**不能用真实串口**。别试图绕过——这是浏览器安全模型。
   正确做法：本地用静态 HTTP 服务访问；页面上把原因明确告诉用户（检测 `window.isSecureContext` 与 `navigator.serial` 分别给出不同文案）。
2. **用户手势是授权门槛**。`requestPort()` 必须在真实用户点击的调用栈里调用，不能放在 `setTimeout`、`await` 之后或页面加载时自动触发。
3. **零依赖 + 禁 eval**。绘图、FFT、CRC、表达式求值全部自研；用户可填写的任何「公式/配置」都不能走 `eval` / `new Function`，
   否则「导入别人的配置文件」就等价于「执行别人的代码」。本项目用 `expr.js`：词法分析 → 调度场转 RPN → 栈式求值，函数白名单。

## 二、Web Serial 七个坑位（照做，别现场踩）

1. **参数不能热改**。`baudRate` / `dataBits` / `stopBits` / `parity` / `flowControl` 只在 `port.open()` 时生效。
   改参数必须 `close()` → `open()`，并且要**去抖**（本项目 250ms），否则用户拖下拉框会把端口反复开关。
2. **释放顺序固定**：`reader.cancel()` → `reader.releaseLock()` → `writer.releaseLock()` → `port.close()`。
   顺序错了会抛 `TypeError: Cannot release a readable stream reader that is locked` 或静默泄漏读锁，导致再也打不开。
3. **断开与重连交叠必然竞态**。用户点断开后立刻点连接、或设备热拔时，会有两个读循环同时活着。
   解法：一个递增的 **epoch（代次）**，每次连接/断开 `epoch++`；读循环持有自己的 `myEpoch`，发现 `myEpoch !== epoch` 就
   静默退出并直接丢弃已收到的数据。再加 `keepReading` / `disconnecting` 两个布尔标志控制正常收尾路径。
4. **硬流控与手动 RTS 冲突**。`flowControl: "hardware"` 时 RTS 由硬件掌管，此时调 `setSignals({ requestToSend })` 会打架；
   正确做法是检测到硬流控就不传 `requestToSend`，并在界面上说明。
5. **DTR 复位窗口**。Arduino / ESP 类板子打开串口时 DTR 拉低会触发复位，接下来的 1~2 秒内发指令会被 bootloader 吃掉。
   打开成功后记一个 `resetUntil = now + resetWaitMs`，其间禁用发送并给出提示。
6. **页面退出必须释放端口**。在 `beforeunload` 与 `pagehide` 里 `keepReading = false` + `reader.cancel()` + `port.close()`，
   否则用户强关标签页后设备被占用，下次打开报「端口忙」。
7. **写操作要串行化**。`port.writable.getWriter()` 不能被并发持有；用一个 Promise 链（`writeChain = writeChain.then(...)`）
   排队，每笔写完 `releaseLock()`。单笔失败只记录日志，不能让队列断链。

补充：`navigator.serial.addEventListener("disconnect" | "connect")` 能收到热拔/热插通知，配合自动重连（本项目 1.2s 后一次）。

**再补五个（都是界面层的事故级坑，V2.2.1 一次踩全）**

8. **Grid 同排面板会被强行等高**。CSS Grid 默认 `align-items: stretch`，把「监视器」与「波形」放在同一排的多个
   grid 单元里时，监视器一高，波形面板就被拉到同高，canvas 高度被撑爆、y 轴刻度全挤成一条竖线（用户的原话是「时域波形
   稀烂、跟着监视器一起拉长」）。两种解法：给容器加 **`align-items: start`**（面板按自身高度排，最省事），
   或者干脆改成**上下分割**（本项目方案，见 §三之一）。凡是「多面板 + 其中一块明显更高」的布局，
   第一件事就是检查 `align-items`。
9. **跨槽位移 DOM 会打死 canvas**。把已有面板从「工作区槽」搬到「主位槽」时，如果只 `appendChild` 移动节点，
   原来的 `<canvas>` 会被浏览器重置为 0×0（脱离文档流后尺寸归零，移回来也不会自动恢复），波形直接消失。
   正确做法：**移动后重建渲染器**（`destroy()` 旧的 → 在新宿主里 `make()` 新的）。本项目 `views.moveToSlot()` 就是
   销毁 + 重建整块面板 DOM，而不是搬节点。
10. **`syncForms` 刷不到非 `addBind` 控件**。表单回填只认走过 `addBind` 的控件；预设套用、示例帧载入这类
    「程序性改配置」后，帧头/帧尾这类**手工输入的文本框不会被回填**，界面上还显示旧值（用户改了预设却发现输入框没变）。
    解法：单独写一个 `refreshRuleInputs()` 在套用预设/示例后显式回填，并把它挂在配置变更事件上。
11. **状态类 UI 必须订阅真源，不能各自为政**。项目里一度有「圆标读 A 变量、页签读 B 变量、冻结按钮读 C 变量」，
    点了之后三处显示不一致。规矩：**唯一的暂停真源是 `core.state.paused`**，绿圆标 / 页签 / 按钮全部
    `core.on("state", render...)` 订阅它再渲染，谁都不许自己存一份状态。
12. **两套时钟不能混用**。`performance.now()`（单调、适合绘图时间轴）与 `Date.now()`（绝对墙钟、适合显示
    "23:06:40.125"）必须在记录生成时就分开存成 `t` 与 `tWall` 两个字段，下游各自取用。一旦某处用
    `new Date(performance.now())` 显示时间，用户会看到 1970 年。相关实现见 §三之二。

## 三、参考架构：14 个单一职责模块 + 一条单向数据流

单一全局命名空间（本项目 `window.SerialLab`），模块之间**不互相持有引用**，跨模块只走事件总线。

```
util       ── 叶子模块（转义/字节/时间/下载/环境探测），零依赖
core       ── 事件总线 on/off/emit + 运行状态 + 配置默认值/版本迁移/持久化
codec      ── UTF-8 多字节切分保护、按行分帧、按帧头/帧尾/长度字段收帧、四种校验和（另可选「无」）
expr       ── 安全表达式求值（禁 eval）
parser     ── 文本 key=value/冒号解析；HEX 结构表解析（偏移/类型/字节序/缩放 + 校验比对）
fft        ── radix-2 迭代 FFT + 汉宁窗 + 单边幅值谱
datastore  ── 每通道环形缓冲（零分配遍历）+ 通道元数据 + 原始帧记录 + 即时统计
transport  ── Web Serial 状态机 / 读循环 / 写队列 / 参数重开 / 手动信号 / 内置演示数据源
plugins    ── 声明式渲染器注册表 + 内置渲染器 + 描述符校验 + 面板包导入导出
views      ── 面板增删/排序/折叠 + 主位与工作区两槽位路由 + 上下分割比例 + 全屏/收起
             + requestAnimationFrame 节流渲染循环（含暂停闸门）
timeline   ── 录制 / 暂停 / 回放 / 录制文件导入导出 + 帧数上限与滚动淘汰
exporters  ── CSV(带 BOM)/JSON/BIN/TXT 导出、配置导入导出、单文件离线版装配
             + **AI 调试包 debugBundle()**（自包含 JSON + 纯文本摘要，见 §九）
ui         ── DOM 绑定、控件与配置双向同步、对话框、提示条、主题、快捷键、发送引擎
             + 显示偏好面板（节流/字号/数字标红/自动存档/恢复默认）、开源协议预设、运行圆标
app        ── 唯一编排者：装配数据管线并启动 + 缓存字节重放（规则热更新）
```

依赖方向严格单向，`app` 是唯一的顶层：

```
util → core → codec → expr/parser/fft/datastore → transport/plugins → views/timeline/exporters → ui → app
```

**数据流（唯一正确的通路）**

```
接收：transport emit "serial:data"
   → app 分帧 → parser 解析 → datastore.pushFrame(自动建通道) + pushRaw(原始记录)
   → emit "frame" → views/plugins 节流重绘；timeline 录制；ui 更新状态灯与计数
发送：ui/发送引擎 → SL.app.send() → transport.write()（写队列串行化）
      注意：发出的内容只进原始记录，绝不把「自己发出去的值」灌进通道，否则曲线会被自己污染
```

**为什么值得这样拆**：`transport` 换成 WebSocket 只要替换一个模块，解析/绘图/录制/导出整条链路原样复用；
`plugins` 加一项就多一种图表；`parser` 的字段表扩成 CAN 报文定义就变成总线调试器。三条路都不碰数据管线其余部分。

### 三·一 主位布局：为什么「监视器占上主区、波形在下」（V2.2.1）

串口调试类工具的信息层级天然是**金字塔**：原始文本流在塔尖（一切结论的源头、排障第一现场），解析后的数值在中间，
图形化视图在塔底（是「已经看懂数据」之后的呈现，不是起点）。所以布局要服务这个层级，而不是把各面板平等摆开。

本项目采用的**上下分割模型**（贴 VOFA+ / SerialWeb 习惯）：

```
主区（.sl-stage）
├─ 上：监视器槽 .sl-stage-main   —— 串口监视器常驻，默认占 62%
├─ 分割线 .sl-split              —— 可拖拽，改的是「比例值」不是高度像素
└─ 下：图表槽 .sl-stage-grid     —— 波形 / 频谱 / 表格等工作区，独立滚动、固定高
```

关键实现约定（换别的技术栈也照这个思路）：

- **比例用 `flex-grow` 数值对表达**，不直接写死高度：主位 `flex-grow: var(--sl-mon-grow)`，
  图表槽 `flex: var(--sl-grid-grow)`，其中 `--sl-mon-grow = ratio×1000`、`--sl-grid-grow = (1−ratio)×1000`。
  拖分割线只改 `ratio` 一个配置值（落盘 `ui.monRatio`，默认 `0.62`），两个槽的高度由浏览器自动分摊——
  比手工算像素稳，且天然自适应窗口。
- **两个槽各自独立滚动**。上下分割的意义就在于「监视器再长也压不到波形」，这与 Grid 同排是本质区别。
- **面板高度必须显式指定**。图表槽里的面板给一个固定高（本项目 `.sl-panel--grid { height: 260px }`），
  **不要靠父容器分配高度**——父容器一旦 `stretch` 就会反过来把 canvas 拉爆（见 §二 第 8 条）。
- **主位只有一个**。用 `enforceSingleMain()` 保证；把某面板「提升为主位」= 把原主位降回工作区 + 目标面板升上去，
  且**必须重建渲染器**（见 §二 第 9 条）。
- **主位支持全屏与收起**：全屏 = 把主区的高度因子拉满、临时隐藏图表槽（`toggleMainFull()`，退出时恢复原比例）；
  收起 = 给主区加一个类把监视器压成一行标题栏（`setMainCollapsed()`），把主区让给波形。
- **落盘**：`sideHidden / monRatio / monCollapsed / drawInterval / fontSize / highlightNumbers / markFailed / autoRecord / recordCap`
  全部进 `core.config.ui`，随配置导出、随「恢复默认」复位。

划分四区（供文档与界面自查）：**A 顶栏**（运行圆标 + 连接状态 + 字号/主题/恢复默认/顶栏入口）、
**B 左栏**（页签式设置：连接 / 收帧 / 解析 / 显示 / 图表 / 发送 / 录制 / 导出）、
**C 主区**（上监视器 + 下图表，可拖拽）、**D 发送条**（贴底，常驻）。判据是「越常用、越需要持续盯住的越靠主视觉中心」。

### 三·二 两套时钟 + 暂停单一真源

- **绘图用 `performance.now()`**（单调递增，不受系统改时间影响），字段名 `t`，相对时长起点；
- **时间戳显示用 `Date.now()`**，字段名 `tWall`，是绝对墙钟。
- 每帧记录**同时**存两个字段（本项目 `mkRec()` 统一构造，避免各处手搓漏字段）；显示层由
  `transport.timeMode` 二选一：`"abs"`（默认）走 `U.fmtClock(tWall)` → `23:06:40.125`，
  `"rel"` 走 `U.fmtRelative(t)` → `1.234s` / `1m00.000s`。**绝不允许拿一个时钟算出另一个**。
- **暂停只有一处真源**：`core.state.paused`。运行绿圆标、工具条按钮、`views.frame()` 的闸门、
  定时轮询的闸门全部读/写它，谁也不许自存副本（见 §二 第 11 条）。暂停 =「停刷新，仍收数据」，
  不是断开连接；回放前自动解冻。

## 四、分帧：比解析更容易出错的一步

串口是**字节流**，一次 `read()` 拿到的块与「一帧」没有任何必然关系。必须在应用层重组。

- **文本模式**：按 `\n` / `\r\n` / `\r` 切行。要点：
  - `\r` 可能是 `\r\n` 的前半，出现在块尾时必须**悬置**到下一块确认，不能立刻切；
  - 空行也要保留（时序线索）；
  - 没有换行的裸流：用**静默超时**兜底（如 60ms 内没有新数据就把残留字节当一行送出去），否则监视器永远空着。
- **HEX 模式**：三种定界方式 —— 帧头、帧尾、长度字段（`mode: payload | total`）。
  - 长度字段的偏移必须明确口径：本项目定义 **offset 是相对「整帧起始」（含帧头）**。
  - **有校验和时，帧长必须加上校验和字节数**。这是踩过的坑：早期公式写成
    `len = head.length + offset + size + payload`，既重复计了帧头、又漏了校验和，导致「带帧头 + 长度字段 + 校验和」的帧永远收不齐。
    正确：`len = offset + size + payload + tail.length + checksumSize`。
  - 找不到帧头时保留末尾 `head.length - 1` 个字节（可能是被切断的帧头）；长度非法（≤0 或超上限）时跳一字节重找，不要整块丢弃。
  - 残留字节同样用静默超时兜底，并给记录打上 `partial` 标记——排障时「残帧长度」本身就是最有用的线索。
- **UTF-8 切分保护**：按起始字节判定应有字节数（`<0x80`→1、`110x`→2、`1110`→3、`11110`→4），尾部不足则整段留到下一块。
  **绝不产出 U+FFFD**，否则中文会变成一串问号。

## 五、解析层

**文本**：一行里可能有多个键值对，用正则 `([A-Za-z_][\w.\-]*)\s*[=:]\s*` 全局匹配，命中后从匹配位置继续找数值；
数值正则覆盖整数、小数与科学计数法（`[-+]?\d*\.?\d+(?:[eE][-+]?\d+)?`）。要点：
- 键后面不是数值（如日志行 `[INFO] temp: ready`）要**跳过该键继续找下一个**，不能整行放弃；
- 手动推进 `lastIndex`，否则刚读掉的数值会被当成下一个键的一部分；
- 后缀数字通道（`temp1`/`temp2`）默认保留为独立通道，无歧义、可测。

**HEX 结构表**：字段声明 `{ key, type, offset, size, scale, big }`，`type ∈ int8/uint8/int16/uint16/int32/uint32/float32`。
- `offset` 相对整帧起始（含帧头），与收帧口径保持一致；
- 有符号类型做二补码还原；`float32` 用 `DataView`（注意 `byteOffset`，切片后的 `Uint8Array` 不是从 0 开始）；
- **任何越界都返回 `{ok:false, reason}`，绝不抛异常**。渲染层必须零崩溃：一个越界字段不能让整页白屏。
- 校验和类型：累加和(8/16)、异或(8)、CRC16-Modbus（多项式 0xA001 反射、初值 0xFFFF）。校验失败不算致命——
  字段已经解出来的值仍然可以画，只在记录上标红并给出「期望值 / 实际值」，这对排障比直接丢弃有用得多。

## 六、数据仓与绘图

**环形缓冲**：每通道一个 `Float64Array` 双缓冲（时间 + 值），写满后覆盖最旧。遍历最近 N 点必须是**零分配**的
（`forEachRecent(n, cb)` 直接按下标算，不 slice），因为绘图每帧都要读，一旦分配就会产生 GC 压力并表现为周期性掉帧。
容量取 3 万点左右是内存与回溯窗口的折中。

**绘图层五个要点**：
1. **DPR 适配**：`canvas.width = cssW * dpr`，然后 `ctx.setTransform(dpr, 0, 0, dpr, 0, 0)`，坐标就能按 CSS 像素写。
2. **节流**：数据可能上百 Hz 到达，屏幕只需要 20~25 fps。用 `requestAnimationFrame` 驱动，内部再按
   `now - lastDraw < interval` 抽帧；**不要**在每个数据到达时直接重绘。
3. **跳过不可见面板**：`getBoundingClientRect()` 判断面板是否滚出视口，滚出去的就不重绘。
4. **单面板异常隔离**：`try/catch` 包住每个面板的 `update()`，出错就把它换成空实现并显示一行提示，
   绝不能因为一个坏面板把整个工作区拖停，也不能每帧刷日志。
5. **配色从主题取**：网格/坐标轴/文字颜色全部读 CSS 变量（本项目 `--sl-grid/--sl-axis/--sl-ink*`，由暗色 `:root`
   与浅色 `html:not([data-theme-early="dark"])` 两套令牌提供），渲染器里不硬编码颜色，否则换主题就瞎。

**自研 FFT**：radix-2 迭代式（先位反转置换，再蝶形），加汉宁窗减泄漏，输出单边幅值谱并按「样本数 × 窗相干增益」归一，
使幅值单位与输入一致。采样率优先取配置值；没有配置时按相邻采样点的时间间隔反推（`1/Δt`）。
点数上限取 8192，且 `nextPow2` 向上取整——输入不足时补零，不要抛错。

## 七、声明式插件：让用户 DIY 显示，但不给执行权限

**描述符 schema**（纯 JSON，无可执行内容）：

```js
{
  type: "timeplot",               // 渲染器 id
  id: "p-xxx", title: "时域波形",
  slot: "grid", h: 260, span: 1,  // 布局三字段（见下，不进 opts）
  channels: ["auto"],             // "auto" = 自动取前 N 个可见通道；也可列具体键名
  expr: "(cur*24)",               // 可选映射公式，用通道名作变量，走安全求值
  axis: { yAuto: true, yMin: null, yMax: null },
  window: 500,                    // 最近多少个采样点
  colors: { "cur": "#3b82f6" },
  opts: { /* 渲染器私有选项，以渲染器 defaults 为白名单 */ }
}
```

**布局字段与 `opts` 必须分开**（这是本项目踩过的坑）：`slot`（落在哪个槽：`"grid"` 工作区 / `"main"` 主位）、
`h`（面板高度 px，必须显式给）、`span`（在工作区栅格里横跨几列）是**面板自身的布局属性**，
由 `views` 消费；而 `opts` 是**渲染器私有选项**，由渲染器自己消费，且以渲染器 `defaults` 为白名单。
早期把三者塞进 `opts` 导致 `validate()` 用 `defaults` 做白名单时把它们当未知键丢掉，布局设置静默失效。
规矩：`validate()` 显式接收并保留 `slot/h/span`，其余才进 `opts` 白名单。

**`validate(desc)` 的契约（这是整个插件系统的心脏）**：
- 归一化 + 自动修正 + 记录问题，**任何情况下都不抛异常**；
- 未知 `type` → 降级为 `table` 并给出原因；`title` 超长截断；`window` 越界夹到 `[10, 100000]`；
  `h` 缺省则取该渲染器 `defaults.h`，`slot` 非法则回落到 `"grid"`；
- 公式编译失败 → 丢弃公式并记录（不因为一个公式毁掉整块面板）；
- `yMin >= yMax` → 改回自动量程；
- 颜色不符合 `^#[0-9a-fA-F]{3,6}$` → 忽略该条；
- 返回 `{ ok, panel, errors }`，`errors` 会被上层汇总成一条提示给用户。

**渲染器接口**：`make(hostEl, panel)` → `{ update(dataProvider), resize(), destroy() }`。
`dataProvider` 由 views 注入（`channels()` / `count(key)` / `forEach(key,n,cb)` / `copy(key,n)` / `stat(key)` / `recentRaw(n)` / `now()`），
**渲染器不直接依赖数据仓** —— 这样渲染器能脱离真实串口单独测试，也保持依赖单向。

**面板包（分享配置）**：`{ kind: "seriallab-panel-pack", version: 1, panels: [...], channels: [...] }`。
导入时校验 `kind` 与 `version`：**版本高于本应用支持值要拒绝并说明**，不要「尽力解析」——那会让新格式的文件在老版本里被
静默改坏。同理，配置与录制文件各自也带 `kind` + `version`。

**内置七种渲染器**（够覆盖绝大多数调试场景）：时域折线、频域谱、柱状图、仪表盘、数据表格、文本监视器、二维轨迹（李萨如/相图）。
界面上统一归入左栏「图表」页签（V2.2.1 起把「插件」这个用户不友好的词改成了「图表」，代码层的 `plugins.js` 名字不变）。

## 八、发送引擎与护栏

四种方式，都收敛到同一个 `send(text, {hex, appendLineEnding, label})`：

| 方式 | 用途 | 要点 |
|---|---|---|
| 手动 | 回车即发 | 记住「上一条」便于重发；HEX 模式支持空格分隔，非法时明确报错 |
| 定时轮询 | 周期性问寄存器 | 用「与配置对账」的方式管理计时器：内容或间隔变了就重建，不用手工同步；最小值 20ms |
| 触发应答 | 收到匹配内容自动回包 | **必须带冷却 + 限流**（本项目 250ms/规则、全局 30 次/秒并提示），否则匹配词与应答内容互相包含会瞬间打满串口 |
| 预设发送 | 常用指令一键发 | 可绑单字符快捷键（焦点不在输入框时才生效）；可填「期望回包」+ 超时，收到就报往返耗时，超时也明确提示 |

护栏三件：① 触发规则冷却；② 全局自动发送每秒上限；③ 定时轮询在「暂停刷新」时暂停，避免堆积后一次性倾泻。

**运行开关的界面约定**（V2.2.1 起）：顶栏左上角一个**绿色小圆标**（本项目 `#slRun`）统一表示运行态 ——
灰色静止 = 未连接、绿色缓慢呼吸 = 运行中、琥珀色 = 已暂停刷新。它**不是**「运行/暂停」两个按钮，
点它就在「运行 ↔ 暂停刷新」间切换。圆标与左栏页签、工具条按钮**共用 `core.state.paused` 一个真源**
（见 §二 第 11 条），所以三处显示永远一致；别再单独造一个「冻结显示」按钮与之并存。

## 九、录制、回放与导出（把调试变成可复盘的材料）

- **录制**：订阅 `frame` 事件，把每帧的 `{t, dir, rawHex, text, values}` 追加进数组。**只放内存，不写 localStorage**——
  几分钟 50Hz 就有上万帧，写进 5MB 配额只会把配置一起写坏。上限取 20 万帧，达上限自动停止并提示。
- **回放**：按原始相对时间关系把帧重新喂回 `datastore.pushFrame`（时间戳用「当前时间」，这样波形是滚动出来的），
  并给这些帧打 `source: "playback"` 标记，**录制逻辑遇到该标记要跳过**，否则回放会被录进去形成自我复制。
  每帧最多推 500 条，避免一帧内推爆主线程。
- **暂停刷新**：只停止重绘与定时轮询，数据照收 —— 暂停是「看住这一屏」，不是「断开连接」。回放前要自动解冻，否则屏幕上看不到东西。
- **导出**：解析结果 CSV（列 = 出现过的所有通道键）、原始记录 CSV（序号/时间/方向/HEX/文本）、JSON 快照、BIN（原始字节流拼接）、TXT。
  **CSV 必须带 UTF-8 BOM**（`\uFEFF`），否则 Excel 按本地编码猜，中文全乱码；字段含引号/逗号/换行时按 RFC4180 加引号转义，行尾用 CRLF。
- **单文件离线版**：把 CSS 与所有外链 JS `fetch` 回来内联成一个 `.html`。注意两点：
  ① 源码里可能出现 `</script` 会提前闭合外层标签，必须整体转义；② 生成后要明确告知用户
  「file:// 下串口不可用，只能看界面与演示数据」。

### 九·一 给 AI 准备的「调试包」（`E.debugBundle()`）

这是本项目最有价值的一个设计点：**让人类不用来回截图、复制粘贴，AI 就能拿到足以定位问题的全量现场**。
一次导出得到 **一份自包含 JSON + 一段纯文本摘要**，把「AI 排障需要知道的一切」都塞进去：

```js
{ kind:"seriallab-debug-bundle", version:1, generatedAt,
  app:{...}, connection:{...},                      // 版本、连接参数、是否演示模式
  rule:{ active, detail },                          // 当前收帧规则（帧头/帧尾/长度/校验）+ 可读描述
  frameLayout:[...],                                // 帧结构人话说明（每个字段的偏移/类型/字节序/缩放）
  settings:{ transport, display, panels, send },    // 传输/显示/面板/发送的全部配置
  availablePresets:[...],                           // 内置的 4 套开源协议预设，供 AI 对照
  channels:[{key,label,unit,color,precision,source,visible,count,last,min,max,avg,span}],
  stats:{rawRecords,parsedFrames,bytes,tx,rx,failedFrames,failureReasons,sampleWindow},
  samples:[{seq,dir,tAbs,tRel,hex,text,ok,reason,values}],   // 限幅的原始帧样本（成功 + 失败都有）
  failures:[...], hints:[...], brief:"纯文本摘要" }          // brief 是给「只贴文字」的场景
```

设计要点：
- **凡是 AI 需要的都内联**，不依赖用户补充说明：规则 + 帧结构 + 通道统计 + 失败原因 + 样本，一个文件说清整个现场。
- **`samples` 与 `failures` 必须限幅**（本项目截断到合理条数），否则一个 5 分钟 50Hz 的会话能导出几十 MB，粘不进对话。
- **`brief` 是一段可直接贴进聊天框的纯文本**：连接状态 → 规则 → 通道清单与统计 → 失败计数与原因 → 前几条样本 HEX。
  它保证「懒得下文件、只想贴一段文字」的用户也能用。
- **导出前自检**：`brief` 里不允许出现 `undefined` / `NaN` / `[object`（写断言锁住），否则 AI 会读到脏数据。
- **配套「规则热重放」**：`App.replayBuffered(limit)` 用**已缓存的原始字节**按当前规则重新分帧解析，
  于是「AI 建议你把帧头从 `AA55` 改成 `AAAA`」→ 用户改完规则 → 一键重放 → 立刻验证，**不用重烧固件、不用重新采数据**。
  采集与解析解耦，这是「AI 自动化调试硬件」闭环的关键一环。

## 十、工程与合规底线（本项目验收会查）

1. 业务 JS **全部外置**（HTML 里零内联业务 JS），这样静态语法检查能覆盖到；`index.html` 只留静态标记 + 一个首帧主题引导脚本。
2. `localStorage` 键带固定前缀（本项目 `humanoid-serial-config-v1`），便于站点自检白名单。
3. 双主题：暗色 `:root` 令牌 + 浅色 `html:not([data-theme-early="dark"])` **单选择器**覆盖；
   首帧由 `<head>` 内联脚本写 `data-theme-early`，否则浅色用户会看到深色闪烁。
4. 所有文字对比度 ≥ 3.0（站点有对比度审计脚本会扫）。
5. 禁止空 `class=""` 与一次性私有类名；类名带统一前缀（本项目 `sl-`）。
6. 每个模块文件尾保留 UMD 尾，供 Node 校验脚本 require 真源断言。
7. 不显示、不记录任何密钥/账号/本机路径；串口数据不出本机（没有任何上报代码）。

## 十一、验收清单

**纯函数与管线断言**（本项目 `_本地工具/校验串口应用.js`，必须全过）：
- 字节 ↔ HEX 往返；`hexToBytes` 对奇数位/非法字符返回 `null` 而不猜；
- UTF-8 多字节被切断时不产出 U+FFFD；
- 按行分帧含 `\r\n` 跨块、末尾 `\r` 悬置；
- **用演示源生成的帧喂给收帧函数，必须恰好得到一帧且长度正确**（这条能抓住长度公式类回归）；
- 结构表解出的字段值与构造时的编码值一致；校验和类型对已知向量正确；
- 表达式求值：正常算式正确、未绑定标识符被拒、`alert(1)` 被拒；
- FFT 对已知频率正弦的峰值频率落在容差内；
- 环形缓冲绕回后的顺序与统计正确；
- **规则驱动的演示帧与内置 AA55 帧逐字节等价、自定义帧能被自身分帧器收齐并被结构表解出**（防止「演示模式不跟随用户协议」这类假死）；
- 插件描述符校验：未知类型降级、窗口越界夹取、非法公式被丢弃且不抛异常；**布局三字段 `slot/h/span` 被保留而非丢进 `opts` 白名单**；
- 面板包 / 配置 / 录制文件的 kind 不符与高版本被拒绝；
- **时间格式化**：绝对时刻字符串与 `Date` 各分量分解一致（只断言与 `Date` 一致以免时区误报）；
  相对时长毫秒不丢、`59.9996s` 正确进位为 `1m00.000s`；
- **四套开源协议预设端到端**：FireWater / JustFloat / Teleplot / 匿名 V1.0 各造一帧喂进分帧器并解出预期通道；
  匿名 V1.0 示例帧的 SUM8 **错 1 位即被拒**（这条锁住「校验和口径」这类隐性回归）；
- **AI 调试包结构**：字段齐全、计数与实际一致、`brief` 不含 `undefined`/`NaN`/`[object`、`samples` 被限幅。

**浏览器人工验收**：见 `AGENTS.md` 的「手工验收清单」（控件接线与配置落盘 → 演示模式 → 七种图表 → 发送回显 → 录制回放 → 五种导出 → 双主题）。
其中几类最容易被漏掉：① 设备参数与显示开关**改完要刷新一次看是否回填**（只加控件不接线是真实事故，本项目 V2.2.0 修过 14 个）；
② 自定义 HEX 规则进演示模式能出通道（无硬件时的唯一验证路径）；③ **主区上下分割**：拖分割线后监视器与波形各自独立滚动、
波形不被拉长，`ratio` 落盘后刷新页面仍保持；④ **运行绿圆标三态**与页签开关显示一致（同源 `core.state.paused`）；
⑤ **显示设置**：绝对时刻格式正确、时间戳与正文颜色不同、字号改动即时生效、数字标红生效、恢复默认能一键复位；
⑥ **预设套用**：套用后帧头/帧尾输入框立即回填，且用缓存字节重放能出通道；⑦ **AI 调试包**能下载且 JSON 可被 `JSON.parse`。

**浏览器层专项（E2E）**：本项目在 `_本地工具/e2e/e2e_test.py` 里已有**九条**子应用用例兜底
（`serial_shell` / `serial_pipeline` / `serial_export` / `serial_stage` / `serial_run` / `serial_display` /
`serial_preset_bundle` 等），改布局与交互层后要跑全量而非只跑 `--fast`。

**连真机验收**：打开设备 → 参数与固件一致 → 复位等待结束后收发 → 文本/HEX 两模式各解析一路 → 拔插设备看是否能自动重连。

## 十二、二次开发路线（三条，互不冲突）

1. **换传输层**：把 `transport.js` 换成 WebSocket / Web Bluetooth / 串口服务器 HTTP 长轮询，只需保持
   `emit "serial:data"（Uint8Array）+ write(u8)` 这两个接口，解析、绘图、录制、导出整条链路原样复用。
   WebSocket 版尤其简单：`ws.onmessage` 把 `ArrayBuffer` 转 `Uint8Array` 直接 emit。
2. **换协议**：`parser.js` 的字段表扩成完整报文定义（CAN 的 ID/DLC/信号位域、Modbus 的功能码/寄存器映射），
   解析结果仍然是「键 → 数值」，下游一行不用改。
3. **加视图**：在 `plugins.js` 末尾照既有渲染器补一段 `P.register({ id, label, defaults, make })`，
   `defaults` 里带上 `h`（面板高度，**必填**）与需要时的 `slot/span`；面板编辑器 / 快速添加 / 面板包导出会自动带上它，
   **不需要改 ui.js**。新增后记得把 `id → 中文名` 补进两个下拉的**同一数据源**（本项目 `renderPluginTypes()` 同源
   填充左栏「图表」页签的 `#slPluginType` 与舞台栏快捷添加的 `#slQuickAdd`，只填一处会导致舞台栏下拉为空）。
