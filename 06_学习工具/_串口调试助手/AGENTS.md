# AGENTS.md · 串口调试助手子应用

> 本文件是本子应用目录的 AI 会话入口。站点级红线见仓库根 `AGENTS.md`（**先读那一份**，本文件只补本目录特有的约定）。
> 速览与模块契约见同目录 `llms.txt`；从零开发同类应用的完整流程见 `skills/html-webserial-app/SKILL.md`。

## 本目录的性质

- 位置：`06_学习工具/_串口调试助手/`，是**主站入口页**（`06_学习工具/21_串口调试助手.html`，pageId `06-21`）背后的独立子应用。
- 目录名以 `_` 开头 → 站点自检 `一键自检.ps1` 的可索引页过滤（`-notmatch '\\_'`）会**自动豁免**本目录下所有 HTML 的
  search-index / sitemap / page-meta / 内联脚本语法检查，与 `06_学习工具/_作品/` 同一先例。
- **豁免不等于免检**：`*.js` 仍在自检的「外部 JS 语法」与「C4 localStorage 键名前缀」扫描范围内
  （扫描只排除 `_本地工具/`，不排除其他 `_` 目录）。所以：
  - 所有业务 JS 必须**外置**成独立文件（这样才被 `node --check` 覆盖），HTML 里零内联业务 JS；
  - `localStorage` 的键必须以 `humanoid-` / `site-` / `robot-` / `__t` 开头。
- 本目录的 HTML **不进** E2E 的「全站逐页 smoke」（同样因为不在 search-index 里）；为此在
  `_本地工具/e2e/e2e_test.py` 里单列了十余条专项用例（**数量以脚本输出为准，不在此写死**）（`serial_shell` / `serial_pipeline` / `serial_export` /
  `serial_wiring` / `serial_demo_rule` / `serial_stage` / `serial_run` / `serial_display` / `serial_preset_bundle`），
  覆盖外壳与全部模块挂载、演示数据从传输到监视器打印再绘图的整条链路、配置落盘与 CSV 导出、
  控件接线、自定义协议演示出通道、**主区上下分割与「波形不被拉长」反向验证**、**运行绿圆标与暂停真源**、
  显示设置（时间口径/字号/标红）持久化、**开源协议预设套用与 AI 调试包导出**。
  纯函数层的回归仍必须靠 `_本地工具/校验串口应用.js` 的断言——**改完数据管线请务必跑校验脚本**。
  （这条「豁免导致检查盲区」已在 `AUDIT.md` A-71 登记为「有意保留 + 补偿脚本」。）

## 本目录硬规则

1. **零构建 / 零后端 / 零第三方运行时依赖**。不引入 npm、不引入 CDN 上的 JS 库（KaTeX / Three.js 这类站点既有 CDN 也不要用——
   本应用要能在完全离线的环境下跑）。需要的算法自己写（FFT、CRC16、表达式求值都是自研的，别改成引库）。
2. **保守 ES5**。`var` + `function`；禁 `let/const/箭头函数/模板字符串/class/解构/默认参数/展开运算符`。
   运行时 API 可以用 `Promise` / `Uint8Array` / `TextDecoder` / `fetch` / `requestAnimationFrame`（Web Serial 本身就要求新内核）。
3. **禁止 `eval` / `new Function`**。任何「用户可填写的表达式」都必须走 `js/expr.js` 的词法分析 + 调度场 + RPN 求值。
   这是安全边界：面板包 / 配置会被用户互相分享，一旦允许执行代码，导入配置就变成 XSS 后门。
4. **用户可见文本一律 `textContent`**，禁止 `innerHTML` 拼接来自串口、用户输入或导入 JSON 的内容。
5. **业务模块不碰 DOM**。只有 `ui.js` 可以直接操作静态节点，`views.js` 可以建面板骨架。其余模块要保持可在 Node 里加载。
6. **模块间不互相持有引用**，跨模块通信走 `core` 的事件总线。新增跨模块依赖前先想清楚是不是应该发个事件。
7. **每个模块保留 UMD 尾**（`if (typeof module !== "undefined" && module.exports) { module.exports = SL.xxx; }`），
   以便校验脚本 require 真源文件而不是抄一份副本。
8. **不写死站点自检项数**（站点级规则 10 的延伸）：本目录文档不得声称「自检 N 项全绿」，以脚本输出为准。
9. **`.ps1` / `.bat` 一律 ASCII-only**：本目录暂不需要这两个格式，但若将来新增，中文注释会炸脚本（PS 5.1 GBK 事故）。
10. **不改动站点共享数据文件**：`_assets/quiz-bank.js` / `ib-data-*.js` / `quest-data.js` / `path-data.js` / `site-sections.js`
    由站点侧统一维护，本目录只读不改。
11. **面板高度必须显式指定，不靠父容器分配**。工作区面板写死像素高度（`views.stylePanel` 写 `el.style.height`），
    `.sl-grid` 保留 `align-items: start`。Grid 默认的 `stretch` 会让同一行面板强制等高，
    监视器一高就把波形压成竖线——这是 V2.2.1 之前的真实线上事故（AUDIT A-75），**不要"简化"掉这两句**。
12. **暂停只有一个真源**：`core.state.paused`。任何新入口（按钮/快捷键/圆标）都只改它，
    刷新 UI 统一放在 `core.on("state")` 里；不要在点击回调里各刷各的（AUDIT A-77 就是这么来的）。
13. **`syncForms()` 刷不到非 `addBind` 控件**。像 `#slHexHead` / `#slHexTail` 这类自定义接线的输入框，
    改完配置必须走 `refreshRuleInputs()`。新增同类控件记得补进来（AUDIT A-78）。
14. **新增影响解析行为的配置，要同步补进 AI 调试包**（`exporters.debugBundle` 的 `frameLayout` / `settings` / `hints`）。
    调试包是「AI 读得懂现场」的唯一保证，缺字段等于让 AI 瞎猜。
15. **「能保留多少条记录」只许有一个来源**：权威口径是 `datastore.rawCap()`（数据仓容量），
    `ui.recordCap` 经 `app.applyRecordCaps()` 落地到它。**禁止在别的模块再写一个上限**——
    `timeline` 已删除自带的 `MAX_FRAMES`，改为 `effMax()` 跟随数据仓；`setMaxFrames` 不在设值时夹紧
    （会被「先设时间线后设数据仓」的顺序夹到旧值）。UI 与调试包显示的一律是**真实生效值**，不是配置期望值（AUDIT A-81）。
16. **对外的数据结构是契约，改了必须同步两处**：`debug-bundle.schema.json`（AI 消费侧的验收口径）
    与 `_本地工具/校验串口应用.js` 的 ⑯ 节断言（反向校验实现产出）。漂移了 AI 不会报错，只会给出看似合理的错误结论。
17. **AI 相关能力一律复用内核真源，不要在 `_本地工具/` 里另写一份解析逻辑**：本地桥直接 `require` 本目录 `js/`
    下 11 个模块的真源（含 `protocol.js` 协议分析），所以「浏览器里看到的」与「AI 拿到的」是同一份。桥里重写一份 = 立刻产生两份口径。
18. **`aichan.js` 不碰 DOM**：AI 通道的开关与状态经 `core.emit("ai:state")` 交给 `ui.js` 渲染，
    与其余业务模块同一条规矩（硬规则 5）。剪贴板写入也归 `ui.js` 的 `copyText()`。
19. **写进 `_本地工具/` 的任何文件都会入库**：不写本机绝对路径/用户名，示例用 `<本项目根目录>` 这类占位符
    （`检查隐私.js` 只认反斜杠形态的 WIN-PATH，正斜杠形态它兜不住）。

## 让 AI 自己读数据（本目录的「第二条产品线」）

浏览器侧**永远无法**被 AI 接管串口（`requestPort()` 必须在真实用户手势调用栈内 + 端口选择是原生弹窗）。
所以「AI 自主读写串口」被拆成四条递进通道，**共用同一份解析内核**：

| 级别 | 通道 | 代码位置 |
|---|---|---|
| L1 | 一键「复制 AI 提示词」 | `js/aichan.js` `buildPrompt()` + `ui.js` `copyText()` |
| L2 | 浏览器 NDJSON 持续落盘 | `js/aichan.js`（File System Access API，句柄不跨刷新持久化） |
| L2 | HTTP 上报到本地收件箱 | `js/aichan.js` + `_本地工具/serial-inbox.py`（Python 标准库，含 PNA 预检回包） |
| L3/L4 | 本地串口桥（可自主迭代） | `_本地工具/serial-bridge/bridge.mjs`（Node + serialport，可作 MCP server） |

桥的用法与 MCP 配置见 `_本地工具/serial-bridge/README.md`；**完整闭环手册（token 预算纪律 / 迭代台账 trial / 现场乱码排查 / 真实 STM32 现场经验）见 `.agents/skills/ai-hardware-debug/SKILL.md`**；闭环是
`read` 采一段 → `assert --expect "rpm>1750; cur.max<3.2"`（退出码 0 通过 / 2 不通过）→ `trial append` 记一轮 → 改代码 → 重烧 → 再跑同一组判据。
`list`/`parse`/`assert`/`trial`/`selftest` **不需要硬件**，回归时先用它们。

改动本目录 `js/` 下任何模块后，请额外跑一次 `node _本地工具/serial-bridge/bridge.mjs selftest`
—— 桥复用同一份真源，它是「内核改动是否破坏 AI 侧解析」的最快反馈。

## 与站点集成的约定（改本应用时需要同步的地方）

| 改动 | 需要同步的文件 |
|---|---|
| 新增 / 重命名本目录的文件 | 站点侧无（本目录被索引豁免）；但 `index.html` 底部的 `<script>` 外链顺序要改 |
| 新增子应用页面（本目录内的 .html） | 无需登记；**但要在站点入口页 `21_串口调试助手.html` 里补链接**，否则自检的相对链接审计会漏 |
| 依赖新的本地资源（图片/字体等） | 相应加入根 `sw.js` 的 `PRECACHE`（自检 C16 会校验存在性） |
| 站点版本号发布 | 本应用显示自带的 `UI.VERSION`（`js/ui.js`），**与站点 `S.VERSION` 不同源**——本应用是可独立拷走的基座，不要把它绑到站点版本上 |
| 入口页文案/数字 | `21_串口调试助手.html`（pageId `06-21`），已登记进 search-index / sitemap / page-meta / 学习地图 / index 卡片 / SITE_SECTIONS / 百度清单 |
| 顶栏快速入口 | **站点侧两处**（本目录不需改）：`_assets/site.js` 的 `ICONS.serial` + `injectChrome()` 里的 `.nav-serial`（覆盖全部内容页），以及首页 `index.html` 静态 `.topnav` 与移动端抽屉里的同款入口；样式在 `_assets/site.css` 的 `.nav-serial` 块（含浅色覆盖、窄屏隐藏、打印隐藏） |

## 验证流程

```bash
# 1) 纯函数与帧管线断言（必须全过，期望输出 SERIAL OK）
node _本地工具/校验串口应用.js

# 2) 站点级自检（JS 语法 + localStorage 键名 + 链接审计 + PRECACHE 存在性等）
node -e "0" ; powershell -ExecutionPolicy Bypass -File "_本地工具/一键自检.ps1"

# 3) 浏览器层（本目录不进全站 smoke，靠十余条专项用例（数量以脚本为准）；需先 pip install playwright）
#    改布局/接线/状态类 UI 时务必跑全量而不是 --fast（专项用例全在全量里）
python "_本地工具/e2e/e2e_test.py"

# 4) 本地桥自检（改了 js/ 下任何模块就要跑；不需要硬件）
cd "_本地工具/serial-bridge" && node bridge.mjs selftest && cd ../..

# 5) 人工浏览器验收（自检覆盖不到本目录的 HTML）
powershell -ExecutionPolicy Bypass -File "_本地工具/启动服务器.ps1"
#    访问 http://127.0.0.1:8123/06_学习工具/_串口调试助手/index.html
#    必测：进入演示模式 → 拖分割线看波形有没有被拉长 → 七种图表框都能画出数据 →
#          点绿圆标暂停再继续 → 发送回显进监视器 → 录制回放 → 各格式导出 →
#          套一套四个开源协议预设 → 导出一份 AI 调试包 → 双主题切换 →
#          点「复制 AI 提示词」→ 开「持续写入本地文件」并确认文件在长 → 开 HTTP 上报并确认收件箱有产物
```
