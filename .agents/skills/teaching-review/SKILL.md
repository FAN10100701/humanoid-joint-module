# 教学写法评测(teaching-review)

评测"讲得好不好读",回答四个问题:详略平衡吗?深入浅出吗(比喻/落地解释)?有实例算例吗?学完能留存吗(小结/思考题/自测/解析联动)?

## 评测循环(五步)

1. **跑底表**:`node _本地工具/教学评测.js`。输出:各板块字数中位/比喻页覆盖/实例页覆盖/自测题中位 + 详略失衡清单 + 零比喻/零实例页清单;CSV 底表写 `docs/审计/_教学评测底表.csv`。**详略档位按知识页四分位自校准**,不是绝对字数标准。
2. **选深读样本**:偏多清单前 2~3 页、偏薄清单前 2~3 页、加 1 页公认标杆作对照(现役标杆:02-07 电机选型计算专题;长页样板:04-19 FOC 图解、08-11 NPU 实战下)。抽样即可,不必全量精读(全量精读属于《知识点评估报告》的职责)。
3. **深读裁决**(每页 8 行内,引原文佐证,引文 ≤30 字):
   - 详略:【过多/合适/过薄】+ 哪几节可砍/该补什么(可砍给字数量级;该补给具体形态:算例/对比表/图/贯穿案例)
   - 深入浅出:比喻/类比有无(引原文);抽象概念有无落地解释
   - 实例:数值算例/worked example 有无(引原文);数字是否只散落在自测解析里
   - 知识点覆盖漏项:该页主题下明显漏讲的关键子知识点
   - 教学质量 1-5 分 + 一句总评
   - 横向结论:本批样本的共性一句话 + "只能改一件事先改什么"
4. **写报告**:`docs/审计/教学写法评测报告_<日期>.md`,结构照《教学写法评测报告_2026-09-06.md》:总览表 → 讲多了清单 → 讲少了清单 → 标杆手法(可复制)→ 比喻/实例缺口 → 口径与局限 → 整改建议(只建议不改页)。
5. **收口**:跑 `_本地工具/一键自检.ps1` 全绿;整改属批量修复(≥10 处)时另写修复摘要入 `docs/审计/`。

## 深读 rubric(标杆页 02-07 提炼的七条可复制手法)

① 公式后立即接全流程算例并给判定(✓/✗+余量%);② 连效率/损耗/安全系数都算进算例;③ 对比表先行再进公式;④ 交互组件默认值=算例参数;⑤ 误区写成"错误认知→正确做法";⑥ 真实型号背书并标"以手册为准";⑦ 自测解析给完整推导链与典型错法。
薄页最该学的一招:**算例闭环** —— 每页至少一个从头算到尾的主算例。长页最该学的一招:**分层导航**(页内 TOC + "赶时间读哪几节/完整读哪些"),先让读者能跳读,再谈砍内容。

## 口径与已知局限(误报高发区,裁决前必读)

- **比喻/实例是标记词法**(词表单源在脚本 RE_META/RE_EXAMPLE):不用"算例"一词但数字贯穿的页(如 08-11"三笔账")会误报"零算例" —— 数值算例裁决以深读为准。
- **动态渲染页字数被低估**:正文在 JS 字符串里的交互页(底表 jsBytes/dynamic 列已标出),不判"偏薄"。
- 03 实操等"以真实工程为内容"的页,风格是手册而非讲义,比喻覆盖低属形态使然,不算硬伤。
- 08 工具页正文薄是工具页性质(既有 A-52 观察项),不在本评测开单。
- 跨版本复评:与《知识点评估报告》《板块评分报告》结论交叉引用,不重复其职责(知识点覆盖面/四维分数)。
