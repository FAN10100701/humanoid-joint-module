# SVG 绘图检查与修复

本站(人形机器人学习站)全部图示为**手写内联 `<svg>`**,已发生过一次性 365 处悬空浅色字、16 处文字溢出、14 处标签重叠的事故(V2.1.16 修版)。本 skill 把当时的修复经验固化为可重复执行的检查循环。规范细节见 `references/rules.md`,问题分类与修法见 `references/taxonomy.md`,两份都要在读完后开工。

## 核心原则

1. **静态先行,目检收口**:静态脚本抓得到的不许留给眼睛;静态抓不到的(重叠、错位、箭头指向错误、语义错误)必须截图逐图目检。评分规则原话:"静态规则只做筛查,评分结论以截图目检为准"。
2. **口径单源**:浅色字/溢出的核心判定算法与 `_本地工具/板块评分.js` 保持一致,不得出现"评分脚本说 0 处、本 skill 说 5 处"的分裂。改口径必须两处同步。
3. **修一处,验一处**:每次修改后重跑审计脚本;截图循环里每次修改后重新截图。禁止"攒一批修复最后统一验证"。
4. **双主题是底线**:每张图在浅色与深色主题下都必须可读。硬编码浅色 hex 是事故根源,拿不准就用 `#64748b` 或 `.my-*` 双主题类对。

## 检查流程

### Step 1 静态审计

```bash
# 单页(修复循环常用)
node .agents/skills/svg-diagram-check/scripts/svg_audit.js "06_软件与算法/19_FOC算法完全图解_流程与运行图.html"

# 整个目录 / 全站
node .agents/skills/svg-diagram-check/scripts/svg_audit.js "10_NPU与数字IC设计"
node .agents/skills/svg-diagram-check/scripts/svg_audit.js --all

# 机器可读(交给脚本/循环判断用)
node .agents/skills/svg-diagram-check/scripts/svg_audit.js --all --json
```

输出分级:**[E] 错误**(必须修,悬空浅色字/文字溢出/marker 悬空引用或重复 id/SVG 结构损坏),**[W] 疑点**(需目检裁决:疑似重叠/字号过小/缺图注/缺 aria/元素越界/根缺 font-family)。退出码:有 E 时为 1。

### Step 2 修复 E 级并复跑

按 `references/taxonomy.md` 对应修法修改,改完立即重跑该页审计,直到该页 E=0。W 级逐条裁决:确认为真问题则当场修,误报则忽略并在心里记下该页的"已知误报"模式。

### Step 3 截图目检(浅色 + 深色两个主题)

静态 0 错误后进入截图环节。启动本地服务器(项目页面引用相对路径 `_assets/*` 且 KaTeX 走 CDN,不要用 file://):

```bash
powershell -ExecutionPolicy Bypass -File "_本地工具/启动服务器.ps1"   # 127.0.0.1:8123
```

截图两条路径,按优先级:

- **browser-use(首选)**:本会话有 browser-use 能力时,用它打开 `http://127.0.0.1:8123/<URL编码后的页面路径>`,等 KaTeX/字体加载完再截整页图;深色主题用页面主题切换按钮,或直接执行 `document.documentElement.setAttribute('data-theme-early','dark')`(浅色同理置 `light`,需同步写 localStorage `site-theme`)。
- **agent-browser(备用)**:browser-use 不可用时,用本机可用的 agent-browser CLI 驱动截图(先 `--help` 确认用法,不要猜参数);两者都不可用则降级为仅静态审计+人工目检,并在摘要中注明未做截图环节。

截图三条血泪纪律:

1. **本站有 Service Worker 预缓存(sw.js)**:改完文件直接 reload 看到的仍是旧图!必须在 URL 后加 `?v=N` 之类参数绕过 SW,否则会"明明改了却没生效"白白排查。
2. **截图通道偶发超时**:报错后等 3 秒重试一次;仍失败就关闭标签页重开,不要原地反复重试。
3. **8123 被占用/连接即断时**(常见于并行会话残留多个服务器进程竞争端口),用 skill 自带的备用服务器:`node .agents/skills/svg-diagram-check/scripts/shot_server.js`(127.0.0.1:8199,项目根为文档根),用完 Ctrl+C 停掉。

截图要求:**整页 full-page 截图 + 对每个重点 SVG 单独放大截图**(流程图密集页逐图截)。一张整页图看不了细节,等于没截。

### Step 4 逐图目检清单(每张图过一遍)

1. **可读性**:浅色/深色主题下每一段文字都看得清?尤其图例、轴标签、小注释。
2. **文字**:有溢出图框/出画布?长文案是否拆行合理?与邻近元素有无重叠压盖?
3. **箭头与连线**:箭头有 marker(不是裸线收尾)?指向正确?回流线不穿过主链节点?线不穿过文字?
4. **框与对齐**:盒内文字有留白?同行元素对齐?间距 ≥ 字号?
5. **图注**:每图有 `my-fig-cap` 图注(图① xxx 格式)?编号连续?
6. **颜色语义**:蓝=主流程/信号、橙=警示/强调、绿=成功/正常、红=错误/禁止、灰=注释。同图内不混用。
7. **公式**(若有):KaTeX 渲染无报错红字,长公式不撑破图卡。
8. **删一个元素**:frontend-design 经验——完稿前问"哪条线/哪个标签可以删掉",删掉它。

### Step 5 修复并复截,直到完美

发现问题→按 taxonomy 修法改→重新截图对比→直到该页清单 8 项全过。**单页循环上限 5 轮**,仍不过关说明布局方案有问题,应重排版面(改坐标分组)而不是继续微调。

### Step 6 收口(全站批次时)

- 全站批次修完后跑 `node _本地工具/板块评分.js` 复核浅色字/溢出归零,与本次修复数对账。
- 批量修复(≥10 处)在 `docs/审计/` 写修复摘要(日期+页数+处数+手法),结构性 bug 按 AUDIT.md 约定回写台账。
- 跑 `_本地工具/一键自检.bat` 确认一键自检全绿(项数以脚本输出为准),无回归。

## 修复手法速查(详见 references/taxonomy.md)

| 问题 | 钦定修法 |
|---|---|
| 悬空浅色字 | 换 `#64748b`(双向可读中性灰)或改 `.my-*` 双主题类对;深底图卡内可保留浅字 |
| 文字溢出 | 缩短文案 > 拆行(tspan dy) > 拆图;`text-anchor` 配合调 x |
| 标签重叠 | 移位错开 > 加引线 > 分层(y 错行) |
| 箭头缺失/错向 | 补 `marker-end="url(#id)"`,id 必须页内唯一且已定义 |
| 缺图注 | 补 `<div class="my-fig-cap">图① xxx</div>` |

## 常见坑

- **marker 的 fill 是硬编码色,不随主题变**——深色主题下深色箭头会隐形,选色要用双向可读色。
- **深底白名单是自动识别的**:`.my-fig/.my-svg` 深背景、或图内最大 rect 铺满(≥70%×60%)且深色时,浅字合法,脚本不会误报;不要为了"清零"把深底图的浅字改成深色。
- **`viewBox="0 0 10 10"` 是 marker 的,不是图的**——统计图幅时排除。
- **PS5.1 下 PowerShell 脚本 ASCII-only**;Node 脚本中文输出沿用 `板块评分.js` 现状即可。
- **文字旋转(-90° 轴标签)不参与溢出/重叠估算**,目检时人眼确认。
- 继承字号的 text(自身无 font-size)静态无法估宽,只查自带字号的;这类文字目检时重点看。
