# 本站 SVG 绘图规范(钦定值)

> 来源:全站 119 页手写内联 SVG 的现状统计 + V2.1.16 修版(365 处浅色字/16 处溢出/14 处重叠)沉淀。新画的图直接按这里的钦定值来,检查也按这里判。

## 1. 画布与结构

- `viewBox="0 0 W H"`:常规图幅 **W 560~780、H 150~430**(现状约 30 种尺寸集中于此区间);流程图横向为主。
- 根元素四件套:`xmlns` + `role="img"` + 中文 `aria-label` + `font-family="Microsoft YaHei,sans-serif"`(写在根上,图内文字继承)。
- 页面内 `<svg` 与 `</svg>` 必须配平。
- 每图包一层图卡 `<div class="my-fig">`,图后跟图注 `<div class="my-fig-cap">图① ××流程</div>`;图注编号全页连续(图①②③…)。图注**文字格式**跨页存在板块级历史风格(「图① ××」圈号 / 「图N ××」无冒号 / 「图N: ××」冒号三种),不做跨页强行统一,页内一致、编号连续即可。全局图卡类 `glass.css` 里也有 `.my-svg`,二者等价,一页内统一用一种。

## 2. 颜色(语义与钦定值)

| 用途 | 色值 | 说明 |
|---|---|---|
| 中性注释/次要文字 | `#64748b` | **双向可读钦定灰**,浅底深底都可读,历史 365 处修复的归一色 |
| 主流程/信号/链接 | `#58a6ff` 蓝 | |
| 警示/强调 | `#f59e0b` 橙 | |
| 成功/正常 | `#22c55e` 绿 | |
| 错误/禁止 | `#ef4444` 红 | |
| 深底专用次要灰 | `#8b98a9` | **仅限深底图卡内**,浅底禁用 |
| 盒底色 | 语义色 + `fill-opacity=".07~.1"` | 一律低透明度,不实心 |

- 文字 fill **禁止硬编码**除钦定色以外的任何色;需要主题区分的文字必须走 `.my-*` 双主题类(见下)。
- 纯白 `#ffffff` 文字只允许出现在深底上。

## 3. 双主题类对

每页页头 `<style>` 内成对定义,浅色为默认值、深色用 `html[data-theme-early='dark']` 覆写:

```css
.my-lg{fill:#26303b}  html[data-theme-early='dark'] .my-lg{fill:#c9d1d9}   /* 图例/大标题 */
.my-t{fill:#b45309}   html[data-theme-early='dark'] .my-t{fill:#fcd34d}    /* 强调文字 */
.my-bwd{fill:#991b1b} html[data-theme-early='dark'] .my-bwd{fill:#fca5a5}  /* 反向/警示红系 */
```

已有类(优先复用,不要另起名):`.my-lg / .my-t / .my-tb / .my-tg / .my-bwd / .my-grn / .my-sub-b / .my-sub-o`(样例见 `10_NPU与数字IC设计/06_深度学习基础与LeNet实战.html:63-66`)。新语义才新增类,且必须成对新增。

## 4. 深底白名单(浅字何时合法)

以下情形浅色文字**合法**,脚本自动放行:

1. 页级 CSS 中 `.my-fig`/`.my-svg` 的 background 为深色(合成后亮度 <0.45);
2. SVG 前文 250 字符内含 `class="…my-fig…"`/`my-svg` 且页级图卡 CSS 为深底;
3. 图内面积最大的 rect 铺满图幅(≥70% 宽 × ≥60% 高)且为深色;
4. 文字坐标落在**任一深色 rect**(亮度 <0.35)的几何范围内(±2px/上 16px/下 6px 容差)——注意是"任一"而非"最近",本项目常见「先画所有盒、再写所有字」的画法,只看最近 rect 会系统性误报(2026-09-05 事故:3 处深盒内合法浅字被误杀改色);
5. 无坐标的 tspan 退回"最近 rect"近似判定。

**两个边界**:文字画在深色 rect **之前**且在盒外(如带引线的悬空标签),不受白名单保护,按玻璃卡底色判;彩色浅字(绿 #86efac/红 #fca5a5 系)不属于"悬空浅色字"(灰性 >40),可读性由目检判断。

## 5. 箭头 marker

钦定写法(全站统一):

```html
<marker id="arB" viewBox="0 0 10 10" refX="9" refY="5"
        markerWidth="7" markerHeight="7" orient="auto-start-reverse">
  <path d="M0,0 L10,5 L0,10 z" fill="#58a6ff"/>
</marker>
```

- id 按「语义+颜色」短命名(`arG/arB/hwArrB/fb/tsArrR…`),**全页唯一**;`marker-end="url(#id)"` 引用的 id 必须已定义。
- marker fill 不随主题,选双向可读色;一图多色箭头就定义多个 marker。
- 线不要裸收尾(无 marker 的连线端点),回流线(`stroke-dasharray`)也要带 marker。

## 6. 字号与文字

- 正文 10~12px,标题/图名 12~14px,**下限 8.5px**(低于 8.5 静态报警)。
- 文字不出 viewBox:估算宽 = 汉字数×字号 + 西文数×0.55×字号,`text-anchor="middle/end"` 换算起点;首尾留 2px。
- 长文案优先缩短,其次 `<tspan x=同x dy="1.4em">` 拆行,最后才拆图;单条公式/文案过长撑破图卡的,拆成两条。
- 旋转文字(`transform=rotate`)仅用于轴标签,不参与静态估算,目检人眼确认。

## 7. 布局

- 主流程从左到右(横向图)或从上到下;回流/反馈线从下方绕行,不穿主链节点。
- 元素间距 ≥ 当前字号;同行盒顶对齐;图例框统一放图底部或右上角,不与主链重叠。
- "视觉结构即信息":编号、线型(实线=主链/虚线=反馈)、颜色都要编码真实含义,不做纯装饰元素;完稿前删掉一个可删的元素。

## 8. 工具纪律

- 检查脚本为 Node 零依赖(只用 fs/path),不引入 puppeteer/playwright 等需安装的依赖。
- 浅色字/溢出判定口径与 `_本地工具/板块评分.js` 一致,两边同步改。
- 全站批次修复后:板块评分复核 → 修复摘要入 `docs/审计/` → 一键自检全绿(项数以脚本输出为准)。
