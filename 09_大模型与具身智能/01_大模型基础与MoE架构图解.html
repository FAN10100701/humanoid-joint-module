1 Transformer 最小知识:只看数据流

丢掉数学细节,记住一句话:每个词都「环顾四周」(注意力) 决定该听谁的话,再各自「独立思考」(FFN),如此堆叠几十层。现代主流大模型全部是 Decoder-only 结构:给定前文,逐词预测下一个词。

📌 机器人视角:VLA 模型(视觉-语言-动作)的底座就是一个 Decoder 堆叠体——视觉 token 与语言 token 一起「环顾四周」,最后输出动作 token。看懂本页,07 板块的 VLA 就通了。

2 稠密 vs MoE:把 FFN 拆成「专家团队」

稠密模型(Dense):每个 token 都要过同一个完整 FFN——参数全激活,算力随参数线性上涨(如 Llama 系)。MoE(Mixture of Experts):把 FFN 换成 N 个「专家」FFN + 一个「路由器」:每个 token 只被送到其中少数几个专家(如 256 选 8),其余专家这轮休息。

稠密MoE
参数量= 激活量总参数大、激活参数小
算力随总参数线性涨只随激活参数涨 → 「大知识量、小算力」
代价简单稳定显存要装下全部专家;需负载均衡防「专家旱涝不均」
代表Llama / Qwen 稠密版DeepSeek-V3(671B/37B)、Kimi K2、GLM-4.5

总参数 vs 激活参数(面试高频):DeepSeek-V3 总参数 671B,但每个 token 每层只路由到 8 个专家(+1 共享专家),激活仅约 37B——所以推理算力接近 37B 稠密模型,知识容量却看齐 671B。「共享专家」每个 token 必过,负责通用知识;「路由专家」按需选择,负责细分知识。

3 KV Cache 为什么贵

自回归生成每出一个词,都要拿着新词去和之前所有词做注意力。为避免重复计算,历史词的 Key/Vector 向量被缓存下来——这就是 KV Cache。它随「上下文长度 × 层数 × 并发数」线性膨胀,长上下文推理的显存大头不是模型权重,而是 KV Cache。由此引出下一页的 MLA(Multi-head Latent Attention):把 KV 压缩到低维隐空间,缓存直接缩一个数量级。

4 本节自测

1. MoE 中「路由器」的作用是?
💡 路由器(通常是个小线性层+TopK)为每个 token 选出得分最高的 k 个专家,只有被选中的专家参与本轮计算——这就是「激活参数小」的来源。
2. DeepSeek-V3 总参数 671B、激活约 37B,意味着?
💡 MoE 的交易:用「显存换算力」。计算量只走激活路径(≈37B),但全部专家权重都要驻留显存——这正是 MoE 部署偏好大显存/多卡的原因。
3. 残差连接的作用是?
💡 每层输出 = 层(输入) + 输入:梯度可以经「捷径」直通浅层,几十上百层也能稳定训练。
4. 长上下文推理时显存大头通常是?
💡 推理无优化器;长上下文×大并发时 KV Cache 可达权重数倍。MLA/量化 KV 都是为它而生。
5. 「共享专家」与「路由专家」的区别?
💡 DeepSeek-MoE 架构的特色设计:共享专家保证通用能力不下放给路由,减轻路由学习负担。
6. VLA 模型与 Decoder 大模型的关系?
💡 OpenVLA/π0/GR00T 等都是「预训练底座 + 动作输出头」范式——大模型知识被机器人直接继承。
📌 本节小结:Decoder=注意力+FFN 堆叠;MoE 用「路由选专家」把知识容量与算力解耦;KV Cache 是长上下文的显存大头,也是 MLA 的靶子。
