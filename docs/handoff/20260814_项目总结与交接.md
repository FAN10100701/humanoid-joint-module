# 追加：机身配色系统与"发黑"根因修复（同日第二轮）

## 项目总结

用户反馈"颜色太黑了，默认改银白色，并提供纯白/金属色/原配色/半透明可选"。本轮完成：
1. **根因修复**：整机发黑不是颜色值问题，而是高金属度 PBR 材质（metalness 0.75~0.92）在 `scene.environment` 缺失时镜面反射无环境可反射、漫反射又被金属度压掉。现用 three 自带 RoomEnvironment 程序化生成环境贴图（无外部 HDR 下载），并加 ACESFilmic 色调映射。
2. **5 种配色方案**：silver 银白（默认）/ white 纯白 / metal 金属色 / dark 原配色（分部件初始色）/ ghost 半透明。桌面底部栏 + 移动端视图抽屉两个下拉同步切换，localStorage('robot-color') 持久化。
3. **兼容修正**：highlight/highlightLink 会覆盖 opacity/transparent/depthWrite，ghost 方案下点击部件会被破坏——新增 schemeOpacityTouchup() 在两个高亮函数末尾恢复方案透明参数（发光高亮保留）。

## 错误地点

- 发黑根因：`initThree()`（原五光源布光之前）无 `scene.environment` 赋值。
- ghost 冲突：`highlight()` / `highlightLink()`（约 2450-2548 行）三个分支无条件改写 opacity/transparent/depthWrite。

## 为什么错误（根因分析）

MeshStandardMaterial 的能量分配：漫反射 ∝ albedo×(1−metalness)，镜面反射依赖环境贴图 IBL。原场景只有 4 个方向光 + 半球光，metalness 0.88 的部件漫反射只剩 12%，镜面只反射出光源小亮点 → 整机观感发黑。灯光加到再亮也只能提亮镜面亮点，无法照亮金属面。

## 关键信息

- **新增文件**：`00_解剖式知识可视化\lib\addons\environments\RoomEnvironment.js`（three r160 官方插件，本地化下载，与本地 three.module.js r160 版本匹配）。
- **可调参数（宏）**：`TONE_EXPOSURE`（曝光，越大越亮）；`COLOR_SCHEMES` 各方案的 color/metal/rough/opacity/depthWrite 全部可调。
- **origMat 备份机制**：applyColorScheme 首次遇到每个 mesh 时把初始材质（含 emissive）存 `userData.origMat`，dark 方案据此恢复——改 PART_COLORS 后无需改配色系统。
- **应用时机（4 处，勿漏）**：buildRobot 缓存复用分支、buildFallbackRobot 之后、URDF 组装完成回调、layoutCompare 对比布局后。新增机型加载路径时需检查是否要补调。
- **不能碰**：highlight 的选中发光逻辑（accentHex/emissiveIntensity 0.5）保持原样，schemeOpacityTouchup 只恢复透明三参数；拆解场景 tdGroup 不参与配色（独立零件教学配色）。
- **r160 版本注意**：无 `scene.environmentIntensity` 属性（r163+ 才有），环境亮度只能靠材质 envMapIntensity 和 TONE_EXPOSURE 控制——已在注释中说明，勿加回该无效赋值。
- **验证方法**：打开主页面应立即整机银白且明显比之前亮；底部栏"机身配色"下拉切 5 档，ghost 档点击任意导航部件后半透明不失效；刷新页面后记住上次选择；切 X1/H1/G1、同屏对比、拆解场景进出后配色保持。
- **遗留风险**：sensor 部件的蓝色 emissive 发光在选中任意部件再切回"整机"后会被 highlight 清零（历史行为，非本轮引入）；ghost 半透明无深度写入时零件穿插处会有前后关系跳变（教学演示可接受）。
