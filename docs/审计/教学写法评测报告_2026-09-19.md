## 二、深读裁决:电机编码器与灵巧手3D拆解(v3.0 重构版)

- **详略:【两极】**——交互层极厚(43 个 STL、12+13+18 件参数面板、剖切/弯曲/K4),文字层极薄:学习目标之后直接进 3D 拆解台,再直接进「本节自测」,全文没有一个讲授性 h2 小节。不走 3D 的读者(移动端加载失败、打印、无障碍)拿到的正文≈0。该补一个 3000~4000 字的「三条传动/光路链」文字讲解节(伺服动力链 / 编码器光路 / 全驱动 vs 欠驱动),把参数面板里的专家式一句话描述扩成讲义。
- **深入浅出:【缺比喻,但有落地句】**——底表判零比喻属实。参数面板偶有画面感佳句可放大:"端头缝光栏把 LED 发散光「切」成一条与刻线等宽的薄光刃"(⑦ 号件)。学习目标是纯清单式("看懂…12 件完整光路:基座法兰 / 轴承 / …"),无一句"为什么这么排"。
- **实例:【算例在延伸节,不在主线】**——K4 四级链路折算器是全页最好的教学件:默认值即算例(17bit/27:1/3arcmin,对应本页 RVGH),瓶颈判定给 ✓/✗ 式结论,且写了误区("很多新手「17bit 编码器很准」的直觉,就在这里被打断")——**正是标杆页 02-07 的手法④⑤**。但它被放在页面末尾"延伸知识点",主线拆解台与之零联动(拆解台里点编码器不提 K4,K4 不回链码盘线数)。
- **知识点覆盖漏项**:①伺服产品②编码器产品各自缺"拆完之后怎么装回去看精度/背隙"的引导句;③号产品 LEAP 装配态视觉可读性差(URDF 零位手指上翘、拼合感弱),弯曲演示是理解全驱动的关键,但它藏在控制条第 4 位,无文字引导先拖它。
- **教学质量:3.5/5**。总评:交互与自测已达标杆水准,输在"文字路径断层"与"主线-延伸零联动"。
- **本轮实测发现并已修复的功能缺陷**(影响教学效率的硬伤,详见《修复摘要_2026-09-19_3D拆解台.md》):弯曲演示滑杆一拖即抛 TypeError(数据键名错位,功能全废);爆炸位移不按装配序累加(RVGH 拆完仍是一台整体上移的电机);编码器光路件拆完仍埋在杯体里;部件目录顺序随网络竞态乱跳;提示承诺的"右键平移"从未实现;爆炸后相机上限不足致零件出画。

## 三、横向结论

本批样本(3D 拆解 v3.0 + 底表复核)共性一句话:**交互页的"讲解"全部押注在零件参数面板上,页面级讲授层缺失,教学效率高度依赖设备能跑 3D**。只能改一件事先改什么:**给 3D 拆解页补一个主线讲授节,并把 K4 折算器从"延伸"提为主线联动**(编码器产品说明里直接给一条"点这里算:36 线码盘经 27:1 到关节还剩多少")。

## 四、标杆手法(本页已有,可复制到其他交互页)

1. K4 折算器:交互组件默认值=算例参数 + 瓶颈红黄绿判定(rubric ④⑤ 全中);
2. 自测题与交互件一一对应(剖切常数 +99、爆炸距离按厚度、URDF 装配各出一题,解析回指页面事实);
3. 零部件 desc 用动词写画面("把发散光「切」成薄光刃"),优于罗列参数。

## 六、口径与局限

- 本轮"教学效率"为定性维度(目标-活动-自测对齐 + 文字路径完整性),无量化脚本,以深读为准;
- 交互页字数被底表低估(正文在 JS 字符串里),3D 拆解页"偏薄"仅指**页面级讲授文字**,不含参数面板/quiz 文本;
- LEAP 手装配态视觉观感问题属模型层(URDF 零位),非写法问题,归图片/3D 修复线,不在本报告开整改单。

## 七、整改建议(只建议不改页)

1. **P1**:3D 拆解页补「三条链」主线讲授节(伺服动力链/编码器光路/全驱动 vs 欠驱动,3000~4000 字,含贯穿案例);
2. **P1**:K4 折算器与拆解台联动:编码器参数面板加"算关节端精度"入口,或 K4 移到编码器产品节之后;
3. **P2**:学习目标三条各补一句"为什么"(如"12 件光路=一路光从生到死的一生");
4. **P3**:同形态交互实验室页(3D实验室)复用同一讲授节模板,保持板块内写法统一。
