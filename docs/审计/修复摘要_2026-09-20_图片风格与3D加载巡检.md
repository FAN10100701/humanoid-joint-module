## 三、3D 模型(gz 覆盖与加载链路)

### 1. 补齐 33 个缺失 .gz(A-18 验证项落地)
- 台账 A-18 要求"删除原始 STL 前须验证 gz 全覆盖"——实测:**198 个原始 STL 只有 165 个 gz**,
  缺口集中在 encoder(12)/leap_hand(8)/rvgh_servo(13) 三组(该三组此前完全无压缩格式)。
- 补齐:`gzip -9` 生成 33 个 `.gz`(命名与加载器约定一致:`x.stl` → `x.stl.gz` 追加式),
  **逐一解压与原 STL 字节比对一致**;覆盖率 165/198 → **198/198(100%)**。
- 最大收益:leap_hand `palm_lower.stl` 4.35MB → 1.09MB(-75%)。

### 2. 灵巧手拆解页加载器升级
- 排查发现该页不共用 `app.module.js` 的 drc→gz→STL 三级降载,而是自备 `loadSTL()` 直连原始 STL
  (清缓存实测:43/43 请求全部直连 `.stl`)——33 个新 gz 对该页原本无效。
- 修:`00_3D解剖/电机编码器与灵巧手3D拆解.html` 新增 `fetchSTLBuf()`——gz 优先
  (浏览器内置 `DecompressionStream` 流式解压),不支持/404/解压异常自动回退原始 STL,ES5 兼容。
- 实测(清空 SW 缓存模拟新访客):**43/43 全部走 `.gz`,0 个原始 STL 请求**,渲染探针正常出图。
- `00_3D解剖/sw.js`:`SW_VERSION` v32→v33(该页 HTML 会进 3D 版运行时缓存,按约定 bump 刷新;
  模型缓存 MODELS_CACHE 不动——模型内容未变更,仅新增文件按 URL 首次请求入缓存)。

## 一、新工具:_本地工具/svg_text_contrast.js(零依赖)
- 逐 <svg> 块内全部 <text>/<tspan> 的 fill(含 style 形式),对有效底色算 WCAG:优先级=自带满幅画布 > 不透明色块命中 > rgba 半透明合成(浅/深两底) > 页底(浅/深两底)。
- 建模 rect 的 opacity/fill-opacity 属性(初版漏掉曾致误伤 182 处,已回滚重做);fig-t-* 类按调色板解析真实生效色(验证闭环);阈值:小字 4.5 / 大字加粗 3.0。
- CLI 直跑输出报告退出码(供自检 C18),亦可 require 复用分析函数(修复器同源解析,口径单源)。
