# 题库 Schema 统一方案 · 2026-09-19(优化路线图批次 3-1)

> 背景:全站三套题目数据并存,扩容需分别维护、字段语义不一致。本文档先定"最小统一字段集"与渐进迁移路线;**存量数据本轮不动**,新题自方案采纳起新 schema 入场。

## 一、现状三套 Schema

| | ib-data-a/b/c/d.js(面试题库) | quiz-bank.js(自测题库) | quest-data.js(闯关) |
|---|---|---|---|
| 规模 | 254 题 / 27 学科(四文件 677KB) | 60 题 / 4 组(32KB) | 5 大陆 21 关 + 27 自建题(27KB) |
| 顶层结构 | `IB_X = { subjects:[…], items:[…] }` | `QUIZ_BANK = [ … ]` | `QUEST_BANK = { worlds, levels, Q }` |
| 题目字段 | `id, s, q, lv, tags, a(HTML), svg?, formula?, follow?, extend?, links?` | `id, g, q, o[4], a, e` | 引用 `q:/qb:/ref:` + 自建题 `Q.qXXX` |
| 判分方式 | 自评(星级)+参考答案 | 客观(单选字母) | 客观(q/qb)+ 自评(ref) |
| 消费页 | 11_面试题库 | 03_自测题库、srs.js | 12_闯关学习 |
| 自检锚定 | C3/C13(SITE_STATS 口径)、面试题数同步 | Quiz bank sync(60 vs 60) | C11(qs 三种引用完整性) |

## 二、问题

1. **三处扩容三套口径**:加题要分别遵守三套字段约定,解析字段名(e/a)、标签(tags/g)、难度(lv/无)互不相同;
2. **富文本边界不一**:ib 的 `a` 是 HTML(依赖 sanitizeHTML 纵深防御),quiz-bank 的 `e` 是纯文本,新题维护者易混用;
3. **题干选项格式耦合**:quiz-bank 选项带 "A. " 前缀写死在数据里,渲染层无法自定义排版;
4. **quest 三种引用协议**是优势(复用不复制),但 `Q` 自建题与 quiz-bank 字段又不同,学习成本高。

## 三、最小统一字段集(提案)

新增适配层 `_assets/qbank-core.js`(仅约定,不搬数据),定义规范题对象:

```js
{
  id: "u100",              // 全站唯一,前缀分源:ib/quiz/quest 自建
  subject: "zkl",          // 学科/组 id(对齐 ib subjects 与 quiz-bank g)
  q: "题干(纯文本)",
  opts: ["选项1", …],      // 2~4 项,不带字母前缀(渲染层加)
  ans: 0,                  // 正确项下标(数字,替代字母)
  explain: "解析(纯文本或受控 HTML)",
  tags: ["…"],             // 可选
  level: 1..5,             // 可选,复试频率/难度
  kind: "mcq"              // 预留:mcq/short/self(自评)
}
```

配套转换函数(放 qbank-core.js,零依赖 ES5):`QB.fromQuizBank() / QB.fromIbItem()(自评题映射 kind:'self') / QB.fromQuestQ()`——三种存量结构 → 统一对象,供**新消费方**(如未来的统一练习页、AI 出题、数据统计)一次读取全站题库。

## 四、渐进迁移路线(不做大爆炸)

- **第 0 步(本方案)**:定约定 + 提供转换器;存量文件一个不动,三套现有页面照旧;
- **第 1 步**:新题入库规则——自测题新增仍进 quiz-bank(保持 C 锚定),但从"统一字段集"复制字段语义(opts 不带前缀、ans 用下标)写转换说明进各文件头注释;
- **第 2 步(需要时)**:建"统一练习页"直接消费 qbank-core(联合 254+60+27 题),验证转换器覆盖度,发现字段缺口回补;
- **第 3 步(可选,需专项)**:物理合并为单源 JSON + 按需分片。仅当第 2 步稳定、且登记链自动化(路线图 3-4)落地后才考虑;涉及 C3/C11/C13 三个自检锚定同步重写,收益(少两套 schema)对成本(全链回归)比值一般,不强推。

## 五、风险与联动

- sanitizeHTML 纵深防御对 `explain` 受控 HTML 同样生效(转换器不转义,渲染层统一走 Site.sanitizeHTML);
- 自评题(ib)无标准答案,转换器给 `kind:'self'`,消费方不得当客观题判分;
- 单题行超 1KB 的可读性问题(台账 A-23)与本方案正交,物理合并(第 3 步)时可顺带按题换行格式化。
